## 📅 วันที่ 2 — สำรวจเทคโนโลยีที่เราจะใช้จริง

### 🎯 เป้าหมาย: ตอบ "Decision" แต่ละข้อได้ด้วยหลักฐาน

**ขั้น 2.1 — ทดสอบ AI สำหรับ Config Generation จริงๆ**

ทำด้วยมือ ไม่ต้องเขียน code ก็ได้ตอนนี้:

ทดลองที่ 1: เปิด Gemini แล้วส่ง Cisco running-config ไป

Prompt: "นี่คือ running-config ของ router:

[วาง config จริงหรือตัวอย่างไป]

ช่วยสร้าง config สำหรับเพิ่ม VLAN 20 ชื่อ Sales"

สิ่งที่ต้องบันทึก:

- Output ถูกต้องไหม? (verify กับ Cisco syntax)

- ใช้ Token กี่ Token? (เปิด token counter)

- ถ้าส่ง config ยาว 200 บรรทัด token เป็นเท่าไหร่?

ทดลองที่ 2: ใช้ Template Jinja2 สร้าง config แทน AI

Template:

  vlan {{ vlan_id }}

   name {{ vlan_name }}

ใส่ค่า: vlan_id=20, vlan_name=Sales

→ output ถูกต้อง 100% ทุกครั้ง

> **สิ่งที่ได้:** ตัวเลขเปรียบเทียบ Template vs AI → นำไปสนับสนุน decision ว่าจะ mix กันสัดส่วนเท่าไหร่

**ขั้น 2.2 — หาคำตอบเรื่อง RAG ให้ลึกขึ้น**

คำถามที่ต้องหาคำตอบ:

1. เราจะเอา Document อะไรเข้า RAG?

   → Cisco IOS Configuration Guide (PDF มีบน cisco.com ฟรี)

   → CIS Benchmark for Cisco IOS (ต้องลงทะเบียน)

   → MikroTik Wiki

2. Document พวกนี้ใหญ่แค่ไหน?

   → นับหน้า → แปลงเป็น size → ประมาณ vector จำนวนเท่าไหร่

3. ถ้าไม่มี RAG เลย แค่ส่ง running-config + prompt → output ต่างกันไหม?

   → ทดสอบเปรียบเทียบ
