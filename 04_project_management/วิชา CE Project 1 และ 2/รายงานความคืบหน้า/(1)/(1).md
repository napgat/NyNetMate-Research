เอกสารนี้มีเนื้อหา Network Management อยู่มากแล้ว แต่ยังปนงานของกลุ่ม `(2)` และยังขาดรายละเอียดของ Device Inventory, Authentication และขอบเขต MVP ที่ชัดเจน ควรจัดใหม่ดังนี้

## 1. ส่วนที่เก็บไว้ในรายงาน Network Management `(1)`

- Authentication และการแบ่งสิทธิ์ผู้ใช้
- Audit Trail หากยืนยันให้กลุ่ม `(1)` เป็นเจ้าของบริการกลางนี้
- Manual Device Enrollment
- Device Inventory Management
- Network Discovery แบบอ่านข้อมูลอย่างเดียว
- Dashboard & Monitoring
- Network Topology Visualization
- การศึกษาเรื่อง:
    - Network Automation
    - Source of Truth
    - Data Model และ Database Schema
    - SNMP, LLDP/CDP และ Read-only SSH
    - ความแตกต่างระหว่างระบบจำลองกับอุปกรณ์จริง
- ผลทดลอง Rust CLI, SNMP v2c, LLDP และ Containerlab

ชื่อโครงงานทางการยังคงเดิมได้ แต่ควรเพิ่มข้อความว่า:

> ขอบเขตของกลุ่ม (1): Network Management

## 2. ส่วนที่ย้ายไปรายงาน Configuration Automation `(2)`

ย้ายรายละเอียดต่อไปนี้ออก:

- Jinja2 Template และ Configuration Generation
- Configuration Management
- Configuration Deployment
- Version Control ของ Configuration
- Security & Validation และ CIS Rules
- AI Component และ Prompt Engineering
- PII Sensitive Data Masking
- Auto-Rollback
- Backend Module เช่น:
    - `ai_assisted_config`
    - `cis_security_validation`
    - `config_generation`
    - `config_version_control`

ในรายงาน `(1)` กล่าวถึงสิ่งเหล่านี้ได้เฉพาะในฐานะระบบภายนอก เช่น:

> Dashboard รับเฉพาะผลสรุป Security Validation จากกลุ่ม Configuration Automation มาแสดง โดยไม่ตรวจสอบ Configuration เอง

## 3. ส่วนที่ควรย่อ

- รายการ OID ของ SNMP → ย้ายไปภาคผนวก
- DF-01 ถึง DF-14 → สรุปเป็น 5 กลุ่มความสามารถ
- รายละเอียดตารางฐานข้อมูลทั้งหมด → เหลือเฉพาะ Entity และความสัมพันธ์หลัก
- รายละเอียดปัญหาเทคนิคย่อย → เลือกเฉพาะปัญหาที่แสดงการเรียนรู้สำคัญ

Dashboard สามารถย่อเหลือ:

1. ภาพรวมและสถานะล่าสุด
2. Manual Refresh และการแยกสถานะ
3. การแจ้งปัญหาสำคัญ
4. รายละเอียด Device, Interface และ Route
5. Drill-down และการเชื่อมต่อระบบอื่น

## 4. เนื้อหาที่ต้องเพิ่มเติม

### ปัญหาที่ต้องการแก้

- ข้อมูลอุปกรณ์และ Interface กระจัดกระจาย
- ไม่สามารถแยกได้ว่าอุปกรณ์ติดต่อไม่ได้ หรือระบบเก็บข้อมูลล้มเหลว
- ข้อมูลสถานะอาจเก่าแต่ผู้ใช้อาจเข้าใจว่าเป็นข้อมูลปัจจุบัน
- แผนผังเครือข่ายอาจไม่ตรงกับการเชื่อมต่อจริง
- การตรวจสอบสถานะด้วยตนเองใช้เวลาและผิดพลาดได้

### เป้าหมาย

- สร้าง Device Inventory เป็นแหล่งข้อมูลกลาง
- เก็บข้อมูลสถานะจากอุปกรณ์แบบอ่านอย่างเดียว
- แสดงสถานะล่าสุดพร้อมเวลาที่เก็บ
- สร้าง Topology จากหลักฐาน LLDP/CDP
- บันทึกว่าใครเพิ่มอุปกรณ์ สั่ง Discovery หรือ Refresh ข้อมูล

### สิ่งที่ไม่ทำในส่วนนี้

- ไม่สร้างหรือแก้ไข Configuration
- ไม่ส่งคำสั่งเปลี่ยนแปลงไปยังอุปกรณ์
- ไม่ทำ Security Validation เอง
- ไม่อ้างว่าเป็น Real-time Monitoring
- ไม่สแกนเครือข่ายมหาวิทยาลัย

## 5. MVP ที่ควรเขียนให้ชัด

สำหรับกลุ่มสองคน แนะนำแบ่งดังนี้:

**MVP หลัก**

```
Login/RBAC
→ เพิ่มอุปกรณ์ด้วยตนเอง
→ จัดเก็บใน Device Inventory
→ Refresh อุปกรณ์ที่ลงทะเบียนครั้งละหนึ่งตัว
→ เก็บสถานะด้วยสิทธิ์อ่านอย่างเดียว
→ แสดงผลใน Dashboard
→ บันทึก Audit Event
```

**ส่วนขยาย**

- Discovery จาก Seed Device
- LLDP/CDP Neighbor Collection
- Network Topology Visualization
- Refresh หลายอุปกรณ์
- SNMPv3
- การทดสอบหลาย Vendor

Discovery CLI ที่ทำแล้วสามารถรายงานเป็น “ต้นแบบเพื่อพิสูจน์ความเป็นไปได้” ได้ แม้จะจัด Discovery และ Topology เป็นส่วนขยายของ MVP

## 6. Device Inventory ที่ควรเพิ่ม

รายงานเดิมยังกล่าวถึงส่วนนี้น้อยเกินไป ควรเพิ่มว่า Inventory เป็นเจ้าของ:

- `device_id`
- `interface_id`
- Hostname
- Device Type
- Vendor
- Model
- OS และ Platform
- Management Address
- Site/Group
- Active Status
- Credential Reference โดยไม่เก็บหรือเปิดเผยรหัสผ่านใน Dashboard

## 7. ข้อมูลร่วมกับกลุ่ม `(2)`

ควรมีหัวข้อสั้น ๆ ว่า:

|ข้อมูล|เจ้าของ/ผู้ใช้งาน|
|---|---|
|Device และ Interface|Network Management เป็นเจ้าของ|
|Vendor, Model, OS, Platform|กลุ่ม `(2)` ขอผ่าน Data Contract|
|Management Address|ส่งตามสิทธิ์โดยไม่ส่งรหัสผ่าน|
|Credential|แยกสิทธิ์ `READ_ONLY` และ `CONFIG_WRITE`|
|Security Validation Result|กลุ่ม `(2)` เป็นเจ้าของ; Dashboard อ่านผลสรุป|
|Audit Trail|เป็นบริการกลางที่กลุ่ม `(1)` ดูแลตามการแบ่งงานปัจจุบัน|

ควรเตรียม Mock JSON ให้กลุ่ม `(2)` ใช้พัฒนาต่อได้โดยไม่ต้องรอ Inventory เสร็จจริง
