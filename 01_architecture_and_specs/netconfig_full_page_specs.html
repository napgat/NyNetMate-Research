Auth gate

ไม่มี sidebar
Components

Username / Password

Input 2 ช่อง + ปุ่ม Sign in, auto-focus username

Error state

Server-side session

P2 — Device management

Zone 1

จัดการคลังอุปกรณ์

2 tabs
Tab A — Device list

Table columns

Hostname · IP · Vendor · Model · OS version · Type (Switch/Router) · Group · Status · Last seen · Actions

Filter bar

Filter by vendor (All / Cisco / MikroTik / Huawei) + filter by Group + search by hostname / IP

Row actions

Edit (inline drawer) · Delete (confirm modal) · Go to config history · Go to topology · Assign group

Status badge

Online (green) / Offline (red) / Unknown (gray) — จาก ICMP ping ทุก interval ที่ตั้งไว้

Tab B — Add device (Manual)

Mode: Manual Form

กรอก Hostname, IP, Vendor (Cisco/MikroTik/Huawei), Model, OS version, Type (Switch/Router), Group + upload running-config (optional, ระบบ parse ดึง facts อัตโนมัติ)

SSH credentials

username + password/key สำหรับ deploy (เก็บ encrypted, แสดงแค่ masked) — ใช้ร่วมกัน Credential Profile

SNMP credentials

community string (Read-Only) สำหรับ Discovery polling (ใช้ PII masking ก่อนส่ง API)

Credential Profile

เลือกจาก Profile ที่บันทึกไว้ล่วงหน้า (เช่น "ชุดรหัสผ่านแผนก IT") แทนการกรอกซ้ำทุกครั้ง

Tab C — Auto Discovery

Discovery Scope

กรอก Seed IP (เริ่มจาก Core Switch แล้วกระโดดตาม LLDP/CDP) หรือ IP Range เช่น 192.168.1.0/24

Credential Profiles

เลือกชุดรหัสผ่านหลายชุด (ระบบสุ่มลองทีละชุดจนกว่าจะเข้าได้) — เช่น SSH Profile, SNMP Community

Protocol & Ports

เลือก Protocol ที่ใช้ scan: SSH (port 22), NETCONF (port 830), SNMP (UDP 161) + กำหนด Timeout

Exclusion Rules

ระบุ IP range ที่ห้าม scan (เช่น Server VLAN, IP ผู้บริหาร) + กำหนด Hop depth limit

Scan Result Review

แสดงรายการอุปกรณ์ที่เจอ พร้อม Vendor/Model ที่ detect ได้ — user ต้อง confirm ก่อนบันทึกลง Inventory

Vendor Detection

ใช้ SNMP sysDescr + SSH banner fingerprinting ตรวจ vendor/OS → เรียก Driver Plugin ที่ตรงกันมาดึงข้อมูล

Tab D — Device Groups

Grouping

สร้าง / แก้ไข / ลบ Group (เช่น "Floor 1 Switches", "Core Routers") — device 1 ตัวอยู่ได้หลาย Group

Bulk assign

เลือกหลาย device แล้ว assign เข้า Group พร้อมกัน — ใช้ filter vendor ช่วยเลือกได้

Group-level actions

สั่ง Generate config หรือ Deploy ไปยัง device ทั้ง Group ได้พร้อมกัน (Nornir parallel execution)

Validation ก่อน save
IP format check→ Duplicate IP check→ Ping reachability (optional)→ Save to inventory DB

P4 — Configuration builder

Zone 2

สร้างชุดคำสั่ง — พระเอกของระบบ

4-step wizard
Step 1 — เลือก device

Device selector

Checkbox list ดึงจาก inventory — เลือกได้หลายตัว, แสดง vendor badge (Cisco / MikroTik / Huawei)

Filter by vendor / group

Filter by vendor เพราะ template แยกตาม vendor + filter by Group เพื่อ batch deploy ทั้ง group

Driver indicator

แสดง Driver Plugin ที่จะใช้กับ device นั้น เช่น "Cisco IOS Driver v1.2" ยืนยันว่า driver พร้อมใช้งาน

Step 2 — เลือก template

Template library

Grid card แสดงชื่อ template + description + vendor badge (Cisco / MikroTik / Huawei) — template แยกต่างหากต่อ vendor

Template categories

VLAN setup · Interface IP · Static route · ACL · OSPF area · NAT/PAT · SSH hardening · Banner · Port security · Spanning tree

Preview

คลิก template → โชว์ preview ว่า output จะหน้าตาเป็นยังไง ก่อน select

AI mode (fallback)

ถ้าไม่มี template ที่ตรง → สวิตช์ไป free-text prompt สั่ง AI แทน — output จะ tag "⚡ AI-generated, review required"

Step 3 — กรอก parameters

Dynamic form

ฟอร์มเปลี่ยนตาม template ที่เลือก เช่น VLAN template → แค่ VLAN ID + VLAN name

Validation inline

IP format check, VLAN range (1-4094), ชื่อห้ามมีช่องว่าง — แสดงทันทีขณะพิมพ์

AI prompt box

Optional textbox สำหรับ context เพิ่มเติมให้ AI — เช่น "ให้ block telnet ด้วย"

Step 4 — Generate
กด Generate→ Backend: PII masking→ Template render (Jinja2) + AI augment 20%→ Unmask PII→ ไป P5 Review

ถ้า API key ไม่ถูกตั้งค่าใน Settings → ระบบ fallback เป็น template-only mode แสดง warning banner แต่ยังใช้งานได้

→ P5 Review & deploy (auto หลัง generate) ← P2 / P3 (เลือก device มาจาก) P7 Settings (ถ้า API key ยังไม่ได้ตั้ง)

P5 — Review & pre-deployment

Zone 3

ตรวจสอบก่อน deploy — จุดสกัดกั้นทุก risk

Gate page
Panel ซ้าย — Code preview

Config output

Syntax-highlighted CLI text — read-only แต่ copyable ทั้งหมด

PII masking status

ไฮไลท์สีเหลืองบรรทัดที่มี sensitive data ที่ผ่าน masking แล้ว เช่น password → *** พร้อม tooltip "masked before API call"

Manual edit

ปุ่ม "Edit" เปิด textarea แก้ได้ก่อน deploy — re-run PII check อัตโนมัติ

Panel ขวา — Security validation

CIS rules checklist

แสดงรายการ rule ที่ pass (✓ สีเขียว) / fail (✗ สีแดง) / not applicable (— สีเทา)

Fail detail

คลิก rule ที่ fail → expand อธิบายว่าทำไมถึง fail + suggestion แก้ไข

Severity

Critical (block deploy) / Warning (แจ้งเตือนแต่ยังไป deploy ได้) / Info

Override

Warning-level สามารถ dismiss ได้ พร้อมกรอก reason — บันทึกใน audit trail

Target device summary

Device list

แสดง device ที่จะ deploy ไป พร้อม current status (online/offline) + Driver Plugin ที่ใช้

Offline warning

ถ้า device offline → แสดง critical warning ห้าม deploy เด็ดขาด

Pre-flight Check (ก่อน Deploy)

Management IP check

ตรวจว่า Config ใหม่ไม่ได้เปลี่ยน / ลบ Management IP ของ device — ป้องกันตัดขาตัวเอง

SSH availability check

ตรวจว่า Config ใหม่ไม่ปิด SSH หรือเปลี่ยน Port 22 โดยไม่ตั้งใจ

ACL self-lockout check

ตรวจ ACL ใหม่ว่าไม่มี deny ครอบคลุม Management Server IP

Safe Deploy — Commit Confirmed
กด Deploy→ Push config via SSH (via Driver Plugin)→ เปิด Countdown Timer (30-120 วินาที)
Backend ทดสอบ SSH reconnect กลับ→ SSH ติด → Commit! บันทึก version สำเร็จ
SSH ไม่ติดภายใน timeout→ แจ้งเตือน "Connection lost — Manual intervention required" + บันทึก incident log

Commit Confirmed pattern — inspired by Juniper JunOS "commit confirmed X" และ Cisco IOS "configure replace revert timer" เพื่อป้องกัน Management Plane Disconnect

Action buttons
มี Critical fail (CIS หรือ Pre-flight)→ Deploy ถูก disable
ผ่านทุก check→ กด Deploy → Safe Deploy flow → success toast
กด Save only→ บันทึก version ไป P6 โดยไม่ deploy
กด Back→ กลับ P4 แก้ parameters
→ P6 Version control (หลัง save/deploy สำเร็จ) ← P4 Config builder (back)

Audit trail tab

Who/When/What

→ P5 Review (rollback flow) ← P1 Dashboard (activity click) ← P2 / P3 (device history) ← P5 (หลัง save/deploy)

P7 — Settings

System

Model selection

Token budget

ตั้ง max tokens per request (default 8000) เพื่อควบคุม cost + แสดง estimated cost ต่อ operation

Offline mode

Toggle ปิด AI ทั้งหมด → ระบบทำงาน template-only 100%

Section B — User management

User list

รายชื่อ users ทั้งหมด + role (Admin / Operator / Viewer)

Add / Edit / Delete user

Section C — Driver / Plugin Management

Installed Drivers

รายการ Driver Plugin ที่ติดตั้งอยู่ (Cisco IOS, MikroTik RouterOS, Huawei VRP) + version ของแต่ละ Driver

Driver detail

คลิก Driver → ดู supported methods (get_facts, get_running_config, apply_config), vendor docs link

Install new Driver

Upload Driver Package ใหม่ (ZIP / Python file) — ระบบ validate ว่า implement Base Interface ครบก่อน activate

Safe Deploy settings

ตั้งค่า Commit Confirmed timeout (30–300 วินาที) — ระยะเวลา reconnect ทดสอบหลัง deploy ก่อน commit จริง

Section D — Credential Profiles

Profile list

รายการ Credential Profile ที่บันทึกไว้ (เช่น "SSH Admin", "SNMP Read-Only") — เก็บ encrypted

Add / Edit / Delete profile

กรอก SSH username/password/key หรือ SNMP community — Admin เท่านั้นที่แก้ได้

Section E — System Configuration

PII patterns

ดู/แก้ regex patterns ที่ใช้ detect sensitive data — เพิ่ม custom pattern ได้ (เช่น pattern เฉพาะ Huawei VRP)

CIS rules

ดูรายการ rules ทั้งหมด — toggle เปิด/ปิดแต่ละ rule, ดู rule detail + รองรับ rules ตาม vendor

Template library

ดู/แก้ Jinja2 templates แยกตาม vendor — import template file (.j2) เพิ่มได้, export backup ได้

System info

Version, uptime, disk usage, last backup timestamp, active drivers count
