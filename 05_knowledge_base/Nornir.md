- **ประเภท:** เฟรมเวิร์กสำหรับระบบอัตโนมัติ (Automation Framework) ด้วยภาษา Python
    
- **หน้าที่หลัก:** บริหารจัดการระบบฐานข้อมูลอุปกรณ์ (Inventory Management) และควบคุมการรันสคริปต์พร้อมกันจำนวนมากแบบขนาน (Concurrency / Parallel Execution)
    
- **จุดเด่น:** เขียนด้วยภาษา Python แท้ (Pure Python) 100% ทำให้ไม่มีข้อจำกัดในการปรับแต่งตรรกะ (Logic) สามารถนำไลบรารีอื่นๆ อย่าง Netmiko หรือ NAPALM เข้ามาปลั๊กอินใช้งานร่วมกันภายในเฟรมเวิร์กได้อย่างราบรื่น ประมวลผลได้รวดเร็วและประหยัดทรัพยากรระบบ

**คอนเซปต์หลัก: ทำไมโลก Network ถึงต้องมี Nornir?**

หากใช้ Netmiko เพียงอย่างเดียวในการจัดการอุปกรณ์เครือข่าย 100 ตัว สคริปต์จะต้องทำงานแบบลูปเรียงลำดับ (Sequential Execution) โดยเชื่อมต่อเข้าไปทีละอุปกรณ์ สมมติว่าใช้เวลาจัดการตัวละ 5 วินาที ระบบจะใช้เวลาเกือบ 10 นาทีกว่าสคริปต์จะรันจบทั้งหมด

**Nornir** ถูกสร้างขึ้นมาเพื่อแก้ปัญหานี้โดยเฉพาะ มันคือ Automation Framework ที่เขียนด้วย Python 100% หน้าที่หลักของ Nornir ไม่ใช่การเข้าไปตั้งค่าหรือส่งคำสั่งไปยังอุปกรณ์ (ตัวมันเองสื่อสารกับ Router ไม่เป็น) แต่ทำหน้าที่เป็น **ผู้จัดการ (Orchestrator)** ที่ดูแลโครงสร้างภาพรวมดังนี้:

อ้างอิงจาก [เอกสารทางการของ Nornir](https://nornir.readthedocs.io/en/latest/) ผู้พัฒนาได้เปรียบเปรยไว้ว่า **"ให้มอง Nornir เป็นเหมือน Flask ของฝั่ง Network Automation"** หัวใจหลักที่คุณต้องทำความเข้าใจเพื่อใช้งาน Nornir มี 4 แกนหลัก ดังนี้ครับ:

- **Concurrency (การทำงานแบบขนาน):** Nornir สามารถสั่งรันคำสั่งไปยังอุปกรณ์จำนวนมากพร้อมกันผ่านระบบ Threading
    
- **Inventory Management:** จัดการฐานข้อมูลอุปกรณ์ (IP, Username, Password, Group) อย่างเป็นระบบผ่านโครงสร้างไฟล์ (เช่น YAML) และสามารถทำการ Filter เลือกเฉพาะกลุ่มเป้าหมายที่จะสั่งงานได้
    
- **Pluggable Architecture:** เป็นแพลตฟอร์มที่เปิดให้เอาไลบรารีอื่นมาเสียบเป็น "ปลั๊กอิน" (Plugins) เพื่อลงไปทำงานกับอุปกรณ์จริง เช่น `nornir_netmiko` หรือ `nornir_napalm`


### การนำ Netmiko และ Nornir มาพัฒนาร่วมกันในงาน Operation

ในการทำงานจริง Nornir และ Netmiko จะทำงานประสานกันเหมือน "ระบบจ่ายงาน" และ "เครื่องมือปฏิบัติการ"

- **กระบวนการทำงาน:** Nornir จะอ่านฐานข้อมูลอุปกรณ์ว่ามีกี่ตัว จากนั้นจะสร้าง Worker Threads ขึ้นมาแบบคู่ขนาน เมื่อถึงเวลาต้องเชื่อมต่อ ตัว Worker Thread จะเรียกใช้ปลั๊กอิน `nornir_netmiko` เพื่อสร้าง SSH Session เข้าไปรันคำสั่งในอุปกรณ์แต่ละยี่ห้อ (เช่น Cisco, MikroTik, Huawei) ตามชุดคำสั่งที่ได้รับมอบหมาย
    
- **การรวบรวมผลลัพธ์ (Aggregated Results):** เมื่อ Netmiko รันคำสั่งเสร็จ Nornir จะรวบรวมผลลัพธ์ (ทั้งตัวที่สำเร็จและตัวที่ Error) กลับมาเป็น Object ก้อนเดียวให้ระบบนำไปประมวลผลต่อ

**ตัวอย่าง Use Case ในงาน Operation:**

1. **Configuration Backup & Validation:** สั่ง Nornir ให้กระจาย Thread ยิงปลั๊กอิน Netmiko ส่งคำสั่งดึงคอนฟิก (เช่น `show run` หรือ `export`) จากอุปกรณ์ทุกค่ายในเครือข่ายพร้อมกัน และเก็บผลลัพธ์ลงฐานข้อมูลส่วนกลางภายในเวลาไม่กี่วินาที
    
2. **การฝังตัวใน Web Application (Backend Integration):** Nornir เป็น Pure Python จึงสามารถฝังเข้าไปในสถาปัตยกรรมซอฟต์แวร์สมัยใหม่ได้ หากพัฒนาระบบ Backend ด้วยเฟรมเวิร์กอย่าง `FastAPI` ควบคู่กับ ORM อย่าง `SQLAlchemy` คุณสามารถ import Nornir เข้าไปใน API Endpoint ได้โดยตรง เมื่อผู้ใช้งานกดปุ่มบน Dashboard (เช่น UI ที่พัฒนาด้วย React/Next.js) ตัว API จะเรียก Nornir ให้กระจายคอนฟิกไปยังอุปกรณ์เป้าหมายได้ทันที โดยไม่ต้องสลับไปสั่งรัน Shell script ภายนอก นอกจากนี้ยังสามารถส่งข้อมูลที่ดึงมาไปประมวลผลต่อในโมดูล AI หรือ RAG pipeline (เช่น ผ่าน `LangChain`) ได้อย่างไร้รอยต่อ

### Pure Python Framework (ความยืดหยุ่นระดับสูงสุด)

ต่างจากเครื่องมืออย่าง Ansible ที่บังคับให้คุณต้องเขียนโครงสร้างภาษาเฉพาะ (Domain-Specific Language อย่าง YAML Playbooks) Nornir ถูกเขียนขึ้นด้วย **Python แท้ 100%** * **ข้อดีที่เห็นได้ชัด:** หากคุณกำลังพัฒนาระบบ Backend ด้วยเฟรมเวิร์กอย่าง FastAPI หรือจัดการฐานข้อมูลด้วย SQLAlchemy การใช้ Nornir จะทำให้คุณสามารถฝัง (Embed) โค้ด Automation เข้าไปในระบบ Backend ได้โดยตรงแบบไร้รอยต่อ ไม่ต้องเขียนสคริปต์แยกแล้วใช้คำสั่ง Shell ไปเรียกทำงาน


### ระบบจัดการ Inventory (แยกข้อมูลอุปกรณ์ออกจากโค้ด)

Nornir จะบังคับให้เราจัดระเบียบข้อมูลอุปกรณ์ใหม่ทั้งหมด โดยมักจะเก็บในรูปแบบไฟล์ YAML 3 ไฟล์หลัก (ข้อควรระวัง: ในการเขียนไฟล์ YAML เพื่อใช้งานจริง ต้องระวังไม่ให้มีอักขระแปลกปลอมหรือ Citation tags หลุดเข้าไป เพราะจะทำให้ระบบอ่านค่าผิดพลาดและเกิด Runtime error ได้)

- `hosts.yaml`: เก็บข้อมูลเฉพาะของอุปกรณ์แต่ละตัว เช่น ชื่อ, IP, และกลุ่มที่มันสังกัด (เช่น Router ของ Cisco หรือ MikroTik)
    
- `groups.yaml`: เก็บตัวแปรของกลุ่มอุปกรณ์ เช่น ถ้าเป็นกลุ่มของ Huawei ให้ใช้พอร์ต 22 และใช้แพลตฟอร์มเฉพาะ
    
- `defaults.yaml`: เก็บตัวแปรที่ทุกเครื่องใช้ร่วมกัน เช่น Username หรือ Password กลาง

### Concurrency (การทำงานแบบคู่ขนาน)

นี่คือฟีเจอร์ตัวชูโรง เมื่อคุณมีอุปกรณ์ 50 ตัว Nornir จะไม่ได้เชื่อมต่อเข้าไปทีละตัว (1..2..3..50) แต่จะใช้ระบบ Threading แตก Worker ออกไปรันคำสั่งพร้อมๆ กัน (Parallel execution) ทำให้เวลาที่ใช้ในการดึงข้อมูลหรือผลักคอนฟิก (Configuration Generation) ลดลงอย่างมหาศาล

### Pluggable Architecture (ระบบปลั๊กอิน)

ตัว Nornir เปล่าๆ **เชื่อมต่อกับอุปกรณ์เครือข่ายไม่ได้** มันทำหน้าที่แค่จัดการคิว จัดการ Inventory และกระจายงาน (Dispatcher)

- **วิธีการทำงาน:** เมื่อถึงเวลาต้องส่งคำสั่งเข้าอุปกรณ์ Nornir จะเรียกใช้ปลั๊กอินอย่าง `nornir_netmiko` (ส่งคำสั่งดิบ) หรือ `nornir_napalm` (ดึงข้อมูลโครงสร้าง) เพื่อให้ลงไปคุยกับอุปกรณ์แทน\

### ภาพรวมการทำงาน (Workflow) ของ Nornir

1. **Initialize:** โหลดไฟล์ Inventory (`hosts`, `groups`, `defaults`) ขึ้นมาในระบบ
    
2. **Filter:** กรองเป้าหมาย (เช่น "เลือกเฉพาะ Router ที่เป็น Cisco ยี่ห้อเดียว")
    
3. **Run Task:** โยนฟังก์ชัน (Task) เช่น การดึงค่า `show run` ลงไปให้ Worker ทุกตัวทำพร้อมกัน
    
4. **Aggregated Results:** Nornir จะรวบรวมผลลัพธ์จากทุก Thread กลับมาเป็น Object ก้อนเดียวให้คุณตรวจสอบว่า เครื่องไหนทำงานผ่าน (Success) หรือเครื่องไหนเชื่อมต่อไม่ติด (Failed)
    


**ฟังก์ชันและคำสั่งพื้นฐานของ Nornir ที่จำเป็นต้องรู้เพื่อเริ่มต้นเขียนสคริปต์จัดการเครือข่าย สามารถแบ่งออกเป็น 4 ส่วนหลักดังนี้**

### 1. การเริ่มต้นระบบ (Initialization)

คำสั่งแรกที่ต้องเรียกใช้เสมอเพื่อโหลดการตั้งค่าและฐานข้อมูลอุปกรณ์ (Inventory) เข้าสู่ระบบ

- **`InitNornir()`**: ทำหน้าที่อ่านไฟล์คอนฟิก (มักจะเป็น `config.yaml`) ซึ่งในไฟล์นั้นจะระบุตำแหน่งของไฟล์ Inventory (`hosts.yaml`, `groups.yaml`, `defaults.yaml`)
    

```Python
from nornir import InitNornir
nr = InitNornir(config_file="config.yaml")
```

### 2. การคัดกรองอุปกรณ์เป้าหมาย (Filtering Inventory)

ในระบบเครือข่ายจริง คุณมักจะไม่สั่งรันคำสั่งกับอุปกรณ์ทุกตัวพร้อมกัน Nornir มีฟังก์ชันคัดกรองที่ทรงพลัง

- **`filter()`**: ใช้เลือกอุปกรณ์ตามเงื่อนไขที่กำหนดในไฟล์ Inventory
    
```Python
# เลือกเฉพาะอุปกรณ์ที่เป็น Cisco
cisco_devices = nr.filter(platform="cisco_ios")

# เลือกเฉพาะอุปกรณ์ MikroTik ที่อยู่สาขา BKK (สมมติว่ามีการตั้งค่าตัวแปร site ไว้)
bkk_mikrotik = nr.filter(platform="mikrotik_routeros", site="BKK")

# เลือกอุปกรณ์ Huawei ทั้งหมด
huawei_devices = nr.filter(platform="huawei")
```

### 3. การสั่งรันงาน (Running Tasks)

นี่คือหัวใจหลักของการประมวลผลแบบขนาน (Concurrency)

- **`run()`**: ทำหน้าที่รับฟังก์ชัน (Task) และส่งกระจายไปยัง Worker threads เพื่อให้ทำงานกับอุปกรณ์แต่ละตัวพร้อมกัน
    

```Python
from nornir_netmiko.tasks import netmiko_send_command

# สั่งให้กลุ่มอุปกรณ์ Cisco รันคำสั่ง "show ip interface brief"
results = cisco_devices.run(
    task=netmiko_send_command,
    command_string="show ip interface brief"
)
```

### 4. การจัดการผลลัพธ์ (Handling Results)

ผลลัพธ์ที่ได้จากการ `run()` จะอยู่ในรูปแบบ Object พิเศษที่เรียกว่า `AggregatedResult` ซึ่ง Nornir มีเครื่องมือช่วยแสดงผลให้อ่านง่าย

- **`print_result()`**: นำเข้าจาก `nornir_utils` ทำหน้าที่พิมพ์ผลลัพธ์ของแต่ละอุปกรณ์ออกมาบนหน้าจอเทอร์มินัล โดยแยกสีให้เห็นชัดเจนว่าทำงานสำเร็จ (สีเขียว) หรือล้มเหลว (สีแดง)
    

Python

```Python
from nornir_utils.plugins.functions import print_result

print_result(results)
```

---

### โครงสร้างโค้ดพื้นฐานเมื่อนำมารวมกัน (Template)

การนำ 4 คำสั่งพื้นฐานมาร้อยเรียงกันเพื่อให้ทำงานได้จริง จะมีโครงสร้างดังนี้:


```Python
from nornir import InitNornir
from nornir_netmiko.tasks import netmiko_send_command
from nornir_utils.plugins.functions import print_result

# 1. โหลดข้อมูลระบบ
nr = InitNornir(config_file="config.yaml")

# 2. กรองเฉพาะอุปกรณ์ที่ต้องการ (เช่น ต้องการจัดการแค่ Cisco กับ MikroTik รอบนี้)
target_devices = nr.filter(platform="cisco_ios") 
# หมายเหตุ: ในการใช้งานจริงอาจจะเขียนฟังก์ชันแยก Task ตาม platform ได้

# 3. สั่งรันคำสั่งพร้อมกัน
results = target_devices.run(
    task=netmiko_send_command,
    command_string="show version"
)

# 4. แสดงผลลัพธ์
print_result(results)
```
