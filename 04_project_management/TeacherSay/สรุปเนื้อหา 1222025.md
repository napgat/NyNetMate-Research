สรุปเนื้อหา 1/22/2025
================ ชื่อ Project =======================================
Application for network management and configuration automation
แอปพลิเคชันสำหรับการบริหารเครือข่ายและการกำหนดค่าเครือข่ายอัตโนมัติ

Scope ของโปรเจคคือ 
1.สร้าง config ให้ตรงตามความต้องการของลูกค้า(Config เอ๋ย,Document เอ๋ย) (AI หรือ สักอย่าง)
เราสามารถเหล่านี้สร้างให้ได้
 - AI สร้าง (มี Error ปัจจับ)
 - logic สร้างเขียนโค้ดเอง
 - หรือใช้คนมาทำเองก็ได้ อยู่เบื้องหลังเป็น admin

2.Warning วิเคาระห์ config เหตุการต่างๆ (เหตุการณ์ อะไรไป define มา) เก็บไว้อยู่ Server
 - AI สร้าง (มี Error ปัจจับ)
 - logic สร้างเขียนโค้ดเอง
 - หรือใช้คนมาทำเองก็ได้ อยู่เบื้องหลังเป็น admin

3.Version Control : สามารถ Reverse เวอร์ชั่นกลับมาได้ไหม? (2 วันก่อนยังใช้ได้เลย) เก็บไว้อยู่ Server
 - snapshot control กด Save เอง
 - ตั้งเวลา เก็บ config
เพิ่มเติม เป็น Config Schudlueให้ admin ตั้งเวลา ใช้ config ตามเวลา เช่น ตอนเช้าใช้ config ชุดนึง ตอนเย็นใช้อีกชุดนึง
 - ปัญหาคือตัวกลางในการจัดการเวลา ต้องเชื่อม server ตลอดเวลา??

อาจาร์ยเพิ่มเติมว่า เราสามารถใช้ 
Network Discovery
 - active (ส่งข้อมูลออกภายในเครือข่าย) data pane: ARP boardcast, ping interface, traceroute, 
 - passive (ฟังอย่างเดียว) control pane: ไม่ส่งข้อมูล แต่ส่ง command เอาข้อมูล ARP table, IP, Subnet, config อยู่แค่ระดับ

อาจารย์แนะนำว่า sync ข้อมูล (config, log) แนวคิดของ git ทำยังไง

ซึ่งตอนนี้ฉันกลับมานั่งคิดต่อจากที่อาจารย์ให้ฉันทำต่อคือ ให้ไปหาวิธีแนวทางทำตาม Scope ของโปรเจค หลากหลายวิธี ให้ลึกซึ้งโดยสามารถบอกข้อดีข้อเสียของแนวทางต่างๆได้ ตัวอย่างเช่นเพื่อนฉันแนะนำว่าโปรเจคของเราต้องเป็น Deskappนะ แล้วมีโปรแกรมอะไรสักอย่างเพื่อรับส่งข้อมูล ผ่าน network อะไรประมาณนี้คุณช่วยฉันคิดแล้วหาวิธีทำแนวทางโปรเจค ทั้ง 3 Feature ให้หน่อยนะ
