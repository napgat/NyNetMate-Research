# คู่มือโครงสร้างเล่มและรายละเอียดแต่ละบท

โครงนี้เป็นแบบที่พบบ่อยในสถาบันไทย ตรวจกับคู่มือของสถาบันก่อนใช้เสมอ ความยาวที่ให้เป็นเพียงช่วงโดยประมาณ

ไฟล์นี้เน้นงานวิจัย สำหรับ SW_Dev หรืองานพัฒนาระบบให้ใช้ `software-engineering-thesis.md` เป็นหลัก และใช้ `format-*.md` กำหนดรูปแบบเล่ม ไม่บังคับจำนวนหน้า สมมติฐาน แบบสอบถาม หรือหัวข้อประชากรกับงานซอฟต์แวร์ที่ไม่ได้ใช้วิธีเหล่านั้น

เช็กลิสต์ด้านล่างใช้กับงานวิจัยและเฉพาะวิธีที่ใช้จริง ไม่ใช้ตรวจตกงาน SW_Dev เพราะไม่มีตัวแปรหรือสถิติ โครงบทและเลขบทเป็นตัวอย่าง ให้ปรับตามคู่มือ/ไฟล์สถานะ สำหรับ สจล. ทุกประเภทงานตรวจรายการส่งและขั้นตอน Project 1/2 ในหัวข้อรายวิชาของ `software-engineering-thesis.md` เพิ่มด้วย

## 1. ส่วนประกอบของเล่ม

**ส่วนนำ** ปกนอก ปกใน ใบรับรองหรือใบอนุมัติ บทคัดย่อภาษาไทย บทคัดย่อภาษาอังกฤษ (Abstract) กิตติกรรมประกาศ สารบัญ สารบัญตาราง สารบัญภาพ (และคำอธิบายสัญลักษณ์ถ้ามี)

**ส่วนเนื้อเรื่อง** บทที่ 1 ถึง 5 (หรือตามโครงสร้างของงานประเภทนั้น)

**ส่วนท้าย** บรรณานุกรม ภาคผนวก (แบบสอบถาม แบบสัมภาษณ์ หนังสือรับรองจริยธรรม ผลการตรวจเครื่องมือ) ประวัติผู้วิจัย

ตาราง: ชื่อตารางอยู่ด้านบนตาราง เช่น "ตารางที่ 4.1 ..." ภาพ: ชื่อภาพอยู่ด้านล่างภาพ เช่น "ภาพที่ 2.1 ..." ใช้เลขบทนำหน้าเลขลำดับ

นี่คือรูปแบบทั่วไป ถ้ามีไฟล์รูปแบบเฉพาะสถาบันใน `references/format-*.md` ให้ใช้ตามไฟล์นั้น (เช่น สจล. ใช้ "สารบัญรูป" "รูป 1.1" และ "ตาราง 1.1" โดยไม่มีคำว่า "ที่" และชื่อไม่ขึ้นต้นว่า "แสดง...") ส่วนท้ายให้ใส่เฉพาะรายการที่งานและสถาบันกำหนด

## 2. บทที่ 1 บทนำ (ประมาณ 5-12 หน้า)

| หัวข้อ | ต้องตอบอะไร | ข้อผิดพลาดที่พบบ่อย |
|---|---|---|
| ความเป็นมาและความสำคัญของปัญหา | ทำไมเรื่องนี้ต้องศึกษา ช่องว่างความรู้คืออะไร | เล่ายาวเรื่องภาพรวมแล้วไม่ลงที่ปัญหาของงานนี้ |
| วัตถุประสงค์การวิจัย | จะทำอะไรให้ได้ (ข้อละหนึ่งเรื่อง ขึ้นต้นด้วยกริยา เช่น เพื่อศึกษา เพื่อเปรียบเทียบ เพื่อพัฒนา) | วัตถุประสงค์วัดผลไม่ได้ หรือมีหลายเรื่องในข้อเดียว |
| คำถามวิจัย / สมมติฐาน | คำถามที่ตอบได้ด้วยข้อมูล สมมติฐานเขียนให้ทดสอบได้ | สมมติฐานไม่ตรงกับสถิติที่จะใช้ในบทที่ 3 |
| กรอบแนวคิด | ตัวแปรหรือแนวคิดหลักและความสัมพันธ์ ที่มาจากทฤษฎีบทที่ 2 | วาดแผนภาพแต่ไม่มีทฤษฎีรองรับ |
| ขอบเขตการวิจัย | เนื้อหา ประชากร พื้นที่ ช่วงเวลา | ขอบเขตกว้างกว่าที่เก็บข้อมูลได้จริง |
| นิยามศัพท์เฉพาะ | นิยามเชิงปฏิบัติการของตัวแปรหลัก | นิยามวนกับตัวคำเอง หรือไม่ตรงกับเครื่องมือที่ใช้วัด |
| ประโยชน์ที่คาดว่าจะได้รับ | ใครได้ประโยชน์และอย่างไร (วิชาการ / ปฏิบัติ) | อ้างประโยชน์เกินกว่าที่ผลวิจัยจะให้ได้ |

**วิธีเขียนความเป็นมา** เรียงแบบกรวย ได้แก่ บริบทกว้างพร้อมข้อมูลหรืออ้างอิงที่เจาะจง → สิ่งที่รู้แล้วจากงานก่อนหน้า → ช่องว่างหรือปัญหาที่ยังไม่ได้รับคำตอบ → งานนี้จะเติมช่องว่างนั้นอย่างไร ย่อหน้าสุดท้ายควรนำไปสู่วัตถุประสงค์ได้ตรง ๆ

**เช็กลิสต์ท้ายบท**
- [ ] วัตถุประสงค์ทุกข้อเชื่อมกับคำถามวิจัยที่ใช้จริง และสมมติฐานเมื่อระเบียบวิธีต้องการ
- [ ] ตัวแปรในกรอบแนวคิดตรงกับวัตถุประสงค์
- [ ] นิยามศัพท์ตรงกับที่จะวัดในบทที่ 3
- [ ] ข้อมูลหรือสถิติในความเป็นมามีที่มาทุกจุด

## 3. บทที่ 2 เอกสารและงานวิจัยที่เกี่ยวข้อง (ประมาณ 20-40 หน้า ป.โทและเอกลึกกว่า)

**หลักการจัด** จัดตามหัวข้อหรือตัวแปร ไม่ใช่เรียงตามผู้แต่งทีละคน เพราะผู้อ่านต้องการเห็นว่าความรู้เรื่องนั้นไปถึงไหน ไม่ใช่รายชื่องานวิจัย

**โครงที่แนะนำ**
1. แนวคิดและทฤษฎีที่เกี่ยวกับตัวแปรหรือแนวคิดแต่ละตัว (นิยาม องค์ประกอบ การวัด)
2. บริบทของงาน (พื้นที่ องค์กร นโยบาย ที่เกี่ยวข้อง)
3. งานวิจัยที่เกี่ยวข้อง ทั้งในและต่างประเทศ จัดกลุ่มตามประเด็น
4. สรุปและสังเคราะห์ พร้อมเชื่อมไปที่กรอบแนวคิด

**วิธีสังเคราะห์งานวิจัย** ทำตารางสังเคราะห์ (synthesis matrix) ก่อนเขียน แถวคือแหล่ง คอลัมน์คือประเด็น (ตัวแปร วิธี กลุ่มตัวอย่าง ผลหลัก ข้อจำกัด) แล้วเขียนเป็นย่อหน้าที่เปรียบเทียบข้ามแหล่ง เช่น "งานส่วนใหญ่พบว่า... อย่างไรก็ตาม X (ปี) พบว่า... ซึ่งอาจเกิดจากความต่างของกลุ่มตัวอย่าง"

**ความทันสมัย** แหล่งส่วนใหญ่ควรเป็นงานในรอบ 5-10 ปี ยกเว้นทฤษฎีต้นแบบ ควรมีทั้งงานในประเทศและต่างประเทศ และเน้นบทความวารสารที่ผ่านการประเมินโดยผู้ทรงคุณวุฒิ

**ข้อผิดพลาดที่พบบ่อย** คัดลอกใกล้เคียงต้นฉบับ (ทำให้ระบบตรวจการคัดลอกจับได้) บรรยายงานทีละชิ้นโดยไม่เปรียบเทียบ ใส่ทฤษฎีที่ไม่ได้ใช้ในกรอบแนวคิด

**เช็กลิสต์ท้ายบท**
- [ ] ทุกตัวแปรในกรอบแนวคิดมีหัวข้อรองรับ
- [ ] มีย่อหน้าสังเคราะห์ ไม่ใช่แค่สรุปทีละงาน
- [ ] ทุกการอ้างอิงเป็นแหล่งที่ยืนยันแล้ว (ดูกฎความซื่อสัตย์)
- [ ] ปิดบทด้วยการเชื่อมสู่กรอบแนวคิด คำถาม และสมมติฐานตามที่งานนั้นใช้จริง

## 4. บทที่ 3 วิธีดำเนินการวิจัย (ประมาณ 10-20 หน้า)

เขียนให้ผู้อ่านทำซ้ำได้ รายละเอียดเรื่องสถิติและเครื่องมืออยู่ใน `research-methods.md`

**เชิงปริมาณ**
1. รูปแบบการวิจัย (สำรวจ เชิงทดลอง กึ่งทดลอง สหสัมพันธ์ ฯลฯ) พร้อมเหตุผล
2. ประชากรและกลุ่มตัวอย่าง (ขนาด วิธีคำนวณ วิธีสุ่ม)
3. เครื่องมือวิจัย (โครงสร้าง วิธีสร้าง การตรวจความเที่ยงตรง ความเชื่อมั่น)
4. การเก็บรวบรวมข้อมูล (ขั้นตอน ช่วงเวลา ผู้เก็บ)
5. การวิเคราะห์ข้อมูล (สถิติที่ใช้ให้ตรงกับแต่ละวัตถุประสงค์ เกณฑ์การแปลผล)
6. จริยธรรมการวิจัย

**เชิงคุณภาพ** แทนข้อ 2-3 ด้วย ผู้ให้ข้อมูลหลักและเกณฑ์การเลือก (purposive หรือ snowball) เครื่องมือคือแนวคำถามสัมภาษณ์หรือแบบสังเกต และบทบาทของผู้วิจัย แทนข้อ 5 ด้วยวิธีวิเคราะห์ (การวิเคราะห์เชิงเนื้อหาหรือเชิงประเด็น) และการสร้างความน่าเชื่อถือ (triangulation, member checking, audit trail)

**ตารางที่ควรมีในบทนี้** ตารางโยงวัตถุประสงค์ → ข้อมูลที่ต้องการ → เครื่องมือ → สถิติหรือวิธีวิเคราะห์ ช่วยให้กรรมการเห็นความสอดคล้องทันที

**เช็กลิสต์ท้ายบท**
- [ ] วัตถุประสงค์ทุกข้อมีวิธีวิเคราะห์รองรับ
- [ ] เหตุผลของขนาดตัวอย่าง/ผู้ให้ข้อมูลและวิธีเลือกชัดเจนตามระเบียบวิธี ไม่บังคับ N/e กับวิธีที่ไม่ได้ใช้
- [ ] ค่าความเที่ยงตรงและความเชื่อมั่นเป็นค่าจริงเมื่อใช้การประเมินชนิดนั้น (ถ้ายังไม่มีให้ใส่ตัวยึดตำแหน่ง)
- [ ] ระบุเลขรับรองจริยธรรมจริง (ถ้างานเกี่ยวกับมนุษย์)
- [ ] เกณฑ์การแปลผลระบุครบ

## 5. บทที่ 4 ผลการวิเคราะห์ข้อมูล (ประมาณ 15-40 หน้า)

**หลักการ** เรียงผลตามลำดับวัตถุประสงค์ แต่ละหัวข้อมีตาราง (หรือภาพ) แล้วตามด้วยคำบรรยายผลสั้น ๆ ที่ชี้จุดสำคัญ ไม่ไล่อ่านตัวเลขทุกช่อง บทนี้รายงานสิ่งที่พบ ยังไม่ตีความหรืออภิปราย

**โครงที่พบบ่อย (เชิงปริมาณ)**
1. ข้อมูลทั่วไปของกลุ่มตัวอย่าง (ความถี่ ร้อยละ)
2. ผลตามวัตถุประสงค์ข้อ 1, 2, 3 ... (ค่าเฉลี่ย ส่วนเบี่ยงเบนมาตรฐาน ระดับ หรือผลทดสอบสมมติฐาน)
3. สรุปผลการทดสอบสมมติฐานในตารางเดียว (ถ้ามี)

**โครงที่พบบ่อย (เชิงคุณภาพ)** จัดตามประเด็นหรือธีมที่ได้จากการวิเคราะห์ แต่ละธีมมีคำนิยาม ตัวอย่างคำพูดของผู้ให้ข้อมูล (ปกปิดตัวตน) และการตีความสั้น ๆ

**เมื่อยังไม่มีข้อมูล** เขียนโครงตารางพร้อมชื่อและเลขตารางครบ ประโยคแปลผลแบบเว้นช่อง `[ใส่ค่าจริง]` และอธิบายว่าสถิติแต่ละตัวต้องผ่านข้อตกลงเบื้องต้นอะไรบ้าง ห้ามเติมตัวเลขสมมติ

**เช็กลิสต์ท้ายบท**
- [ ] ทุกวัตถุประสงค์มีผลรองรับ ตามลำดับเดียวกับบทที่ 1
- [ ] ทุกตารางมีเลขที่ ชื่อ และถูกกล่าวถึงในเนื้อหา
- [ ] ตัวเลขในคำบรรยายตรงกับตาราง
- [ ] หากใช้สถิติ รายงานค่าที่เกี่ยวข้องครบ (เช่น ค่าสถิติ df ค่านัยสำคัญ ขนาดอิทธิพลตามวิธีที่ใช้)
- [ ] ไม่มีการอภิปรายหรือสรุปเกินข้อมูลในบทนี้

## 6. บทที่ 5 สรุป อภิปรายผล และข้อเสนอแนะ (ประมาณ 5-12 หน้า)

1. **สรุปผล** ทวนวัตถุประสงค์ วิธีการโดยย่อ และผลหลักตามลำดับวัตถุประสงค์
2. **อภิปรายผล** ตีความผลทีละวัตถุประสงค์ เชื่อมกับทฤษฎีและงานวิจัยในบทที่ 2 ทั้งที่สอดคล้องและขัดแย้ง และให้เหตุผลที่เป็นไปได้ของความต่าง เป็นส่วนที่ผู้วิจัยได้แสดงความเข้าใจลึกที่สุด จึงควรมีมุมมองของผู้วิจัยเองเป็นแกน
3. **ข้อจำกัดของการวิจัย** บอกตรง ๆ จะน่าเชื่อถือกว่าซ่อน
4. **ข้อเสนอแนะ** แยกเป็น ข้อเสนอแนะเพื่อนำผลไปใช้ (เฉพาะเจาะจงว่าใครควรทำอะไร) และข้อเสนอแนะสำหรับการวิจัยครั้งต่อไป ทั้งสองต้องสืบมาจากผลหรือข้อจำกัดที่พบจริง

**เช็กลิสต์ท้ายบท**
- [ ] ทุกวัตถุประสงค์มีข้อสรุปและมีย่อหน้าอภิปราย
- [ ] การอภิปรายอ้างงานวิจัยจากบทที่ 2 อย่างน้อยหนึ่งชิ้นต่อประเด็นหลัก
- [ ] ไม่มีข้อสรุปที่ข้อมูลไม่รองรับ (เช่น อ้างเหตุและผลจากงานที่ได้แค่สหสัมพันธ์)
- [ ] ข้อเสนอแนะสืบมาจากผลจริง

## 7. บทคัดย่อและ Abstract

เขียนฉบับสมบูรณ์หลังมีผลและข้อสรุปจริง ความยาวตามเกณฑ์สถาบัน เรียงความสำคัญหรือปัญหา → วัตถุประสงค์ → วิธีดำเนินงาน → ผลหลัก → ข้อสรุป งานวิจัยระบุกลุ่มตัวอย่าง/เครื่องมือ/สถิติตามที่ใช้จริง งานซอฟต์แวร์อธิบายระบบและวิธีทดสอบ ไม่มีข้อมูลที่ไม่อยู่ในเล่ม เพิ่มคำสำคัญและจำนวนคำสำคัญเฉพาะเมื่อคู่มือหรือรูปแบบที่ยืนยันกำหนด ไม่บังคับ 3-5 คำกับทุกสถาบัน

Abstract ภาษาอังกฤษแปลให้สอดคล้องกับบทคัดย่อไทย ใช้ศัพท์ตรงกับที่ใช้ในเล่ม และให้ผู้ใช้ให้ผู้เชี่ยวชาญภาษาตรวจอีกรอบ

## 8. โครงสร้างสำหรับงานประเภทอื่น

**วิจัยและพัฒนา (R&D) / พัฒนานวัตกรรม** บทที่ 3 แบ่งเป็นขั้นตอนการพัฒนา (วิเคราะห์ปัญหา ออกแบบ สร้าง ตรวจคุณภาพโดยผู้เชี่ยวชาญ ทดลองใช้ ประเมินผล ปรับปรุง) บทที่ 4 รายงานผลตามขั้นตอนนั้น และผลของการทดลองใช้ มักมีเกณฑ์ประสิทธิภาพ เช่น E1/E2 ซึ่งต้องใช้ตามนิยามของสถาบัน

**วิศวกรรม / คอมพิวเตอร์ / พัฒนาระบบ** ใช้ `software-engineering-thesis.md` สำหรับ Requirements, Design, Implementation, Testing และ Traceability; สำหรับ สจล. ใช้ `format-kmitl-comeng.md` กำหนดรูปแบบเล่มและตรวจรายการบังคับ SW_Dev จากรายวิชา มีเกณฑ์ยอมรับล่วงหน้าและวิธีทดสอบที่ทำซ้ำได้ ความพึงพอใจเป็นวิธีประเมินเมื่อเกี่ยวกับวัตถุประสงค์ ไม่ใช่สิ่งที่ทุกโครงงานต้องวัด

**วิจัยเชิงผสม** บทที่ 3 อธิบายแบบแผนการผสม (เช่น เชิงอธิบายตามลำดับ หรือเชิงสำรวจตามลำดับ) ว่าส่วนไหนมาก่อน ส่วนไหนเติมส่วนไหน และบทที่ 4 ต้องบอกว่าผลสองส่วนมาบรรจบกันอย่างไร
