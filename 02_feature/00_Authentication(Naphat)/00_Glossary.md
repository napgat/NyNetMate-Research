# คำศัพท์และแนวคิดสำคัญ (Glossary) สำหรับ Authentication & RBAC

เอกสารนี้รวบรวมคำศัพท์และแนวคิดที่เกี่ยวข้องกับระบบ Authentication และ Role-Based Access Control (RBAC) ในโปรเจกต์ MyNetMate (อ้างอิงจากบทวิเคราะห์ MVP)

| คำศัพท์ / แนวคิด               | คำอธิบาย                                                                                                                                                                                                                                                                                                                                                                                                |
| :----------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Argon2id**                   | อัลกอริทึมสำหรับ Hash รหัสผ่านที่ปลอดภัยและแนะนำให้ใช้ในปัจจุบัน ป้องกันการโจมตีแบบ Brute-force และ GPU Cracking ระบบจะใช้ในการเก็บรหัสผ่าน ห้ามเก็บเป็น Plaintext เด็ดขาด                                                                                                                                                                                                                              |
| **Reversible Encryption**      | การเข้ารหัสที่สามารถถอดกลับมาเป็นข้อความเดิมได้ (เช่น AES, RSA) **ข้อควรระวัง:** [OWASP กำหนดว่าห้ามใช้ Reversible Encryption ในการเก็บรหัสผ่าน](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) ต้องใช้ One-way Hashing (เช่น Argon2id) เท่านั้น                                                                                                                     |
| **JWT (JSON Web Token)**       | โทเคนสำหรับยืนยันตัวตนหลังจากการ Login สำเร็จ สำหรับโปรเจกต์นี้จะกำหนดให้มีอายุ (Expiration) 30 นาที                                                                                                                                                                                                                                                                                                    |
| **Cookie Security Attributes** | การตั้งค่า Cookie เพื่อความปลอดภัย: <br> - **`HttpOnly`**: ป้องกันไม่ให้ JavaScript ฝั่ง Frontend (เช่น XSS) อ่านค่า Cookie ได้ <br> - **`Secure`**: บังคับให้ส่งผ่าน HTTPS เท่านั้น (ใช้ใน Production) <br> - **`SameSite=Lax`**: ป้องกันการโจมตีแบบ CSRF                                                                                                                                              |
| **JWT Payload Attributes**     | โครงสร้างข้อมูลพื้นฐานที่จะบรรจุใน JWT: <br> - `sub` (Subject): รหัสผู้ใช้ (User ID) <br> - `jti` (JWT ID): รหัสไม่ซ้ำกันของโทเคน (ใช้สำหรับอ้างอิงการ Revoke) <br> - `iat` (Issued At): เวลาที่ออกโทเคน <br> - `exp` (Expiration Time): เวลาที่โทเคนหมดอายุ <br> - `iss` (Issuer): ผู้ออกโทเคน <br> - `aud` (Audience): ผู้รับโทเคน <br> *หมายเหตุ: ห้ามใส่รหัสผ่าน หรือ PII ที่ไม่จำเป็นลงใน Payload* |
| **Revoke Session**             | การบังคับยกเลิกเซสชันจากฝั่งเซิร์ฟเวอร์ (Server-side) ทำให้ JWT ที่ถูกขโมยไปใช้งานต่อไม่ได้ (ระบบจะตรวจสอบเทียบกับตาราง `auth_sessions` ใน Database เสมอ)                                                                                                                                                                                                                                               |
| **Route / API Protection**     | การป้องกันการเข้าถึง API และหน้าเว็บตามสิทธิ์ (Role) ของผู้ใช้งาน                                                                                                                                                                                                                                                                                                                                       |
| **Backend Enforcement**        | หลักการป้องกันความปลอดภัยที่ต้อง **"บังคับใช้ที่ฝั่ง Backend เป็นหลัก"** การซ่อนปุ่ม หรือปิดการใช้งาน (Disable) บนหน้าจอ UI (Frontend) เป็นเพียงการปรับปรุง UX เท่านั้น ไม่ใช่มาตรการรักษาความปลอดภัยที่แท้จริง                                                                                                                                                                                         |
| **Audit Events (Auth)**        | เหตุการณ์สำคัญด้านความปลอดภัยที่ต้องบันทึกลง Audit Log ได้แก่: <br> - `user.login_success` <br> - `user.login_failed` <br> - `user.logout` <br> - `user.password_changed` <br> - `user.deactivated` <br> - `auth.permission_denied` <br> *(หมายเหตุ: ชื่อ action นี้เป็น canonical name ที่ใช้ทั้งระบบ ถ้า D&M ต้องการฟิลด์ `result` ให้ Backend function อนุมาน result จากชื่อ action เช่น `user.login_success` → result=`success`, `user.login_failed` → result=`failure`)* |
| **Resource Type**              | ประเภทของข้อมูลที่ถูกกระทำ เช่น `user`, `auth`, `device` เพื่อให้ง่ายต่อการ Filter                                                                                                                                                                                                                                                                                                                    |
| **actor_user_id**              | (DTO) ชื่อฟิลด์ในฝั่ง API ที่ Map มาจากคอลัมน์ `user_id` ใน Database เพื่อส่งให้ D&M นำไปแสดงผลว่าใครเป็นคนทำ                                                                                                                                                                                                                                                                                        |
| **occurred_at**                | (DTO) ชื่อฟิลด์ในฝั่ง API ที่ Map มาจากคอลัมน์ `created_at` ใน Database เพื่อใช้บอกเวลาที่เกิดเหตุการณ์                                                                                                                                                                                                                                                                                                 |
| **result**                     | สถานะของเหตุการณ์ มีแค่ 2 ค่าคือ `success` (สำเร็จ) และ `failure` (ล้มเหลว)                                                                                                                                                                                                                                                                                                                           |
| **safe_error_category**        | หมวดหมู่ Error ที่ถูกคัดกรองแล้วว่าปลอดภัย ห้ามมีข้อมูลลับหรือ PII เช่น `authentication_error`, `authorization_error`, `invalid_request`, `server_error`                                                                                                                                                                                                                                              |
| **Out of Scope (P1)**          | ฟีเจอร์ที่ถูก **ตัดออก** หรือไม่อยู่ในระยะ MVP P1 ได้แก่: <br> - OAuth / SSO <br> - MFA (Multi-Factor Authentication) <br> - การยืนยันอีเมล (Email Verification) <br> - การรีเซ็ตรหัสผ่านผ่านอีเมล (Email Reset Password) <br> - ระบบ LDAP / Active Directory <br> - สิทธิ์ระดับฟิลด์หรือทรัพยากร (Resource/Field-level Permission)                                                                     |
