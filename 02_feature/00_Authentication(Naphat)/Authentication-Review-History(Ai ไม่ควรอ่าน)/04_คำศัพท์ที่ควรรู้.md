## คำแก่นที่ต้องเข้าใจ

| คำศัพท์                  | ความหมายใน MyNetMate                                                                    |
| ------------------------ | --------------------------------------------------------------------------------------- |
| **Authentication**       | การพิสูจน์ว่า “คุณคือใคร”                                                               |
| **Authorization**        | การตรวจว่า “คุณทำอะไรได้”                                                               |
| **RBAC**                 | Role-Based Access Control: แบ่งสิทธิ์เป็น Admin, Operator, Viewer                       |
| **Session**              | สถานะการ Login ที่ Server จดจำไว้ เพื่อเชื่อม request หลายครั้งกับผู้ใช้คนเดิม          |
| **Server-side Session**  | ข้อมูล session อยู่ใน Database ฝั่ง Server ไม่ได้อยู่ใน Browser                         |
| **Opaque Session Token** | ค่าสุ่มลับที่ Browser ถือไว้ แต่ไม่มี user ID, role หรือข้อมูลธุรกิจอยู่ภายใน           |
| **Session Cookie**       | Cookie ที่เก็บ opaque token เพื่อให้ Browser ส่งกลับมาอัตโนมัติ                         |
| **Session Store**        | ที่เก็บ session ฝั่ง Server; MyNetMate ใช้ตาราง `auth_sessions`                         |
| **Source of Truth**      | แหล่งข้อมูลที่ใช้ตัดสินจริง; สำหรับ session คือ `auth_sessions` และ `users` ใน Database |
| **Bearer Secret**        | ใครถือ token ดิบได้ คนนั้นใช้ session ได้ จึงต้องป้องกัน token อย่างเข้มงวด             |

## คำเกี่ยวกับ Token และ Database

| คำศัพท์                 | ความหมาย                                                                                 |
| ----------------------- | ---------------------------------------------------------------------------------------- |
| **CSPRNG**              | ตัวสร้างค่าสุ่มที่ปลอดภัยเชิง cryptography; MyNetMate สร้าง token 32 bytes หรือ 256 bits |
| **Raw Token**           | token ดิบที่อยู่ใน Cookie; ห้ามเก็บลง DB, log หรือ JSON                                  |
| **Session Token Hash**  | ค่า `SHA-256(token)` ที่เก็บใน `auth_sessions.session_token_hash`                        |
| **Internal Session ID** | UUID `auth_sessions.id` ใช้ภายใน Database/Audit เท่านั้น ห้ามนำไปใส่ Cookie              |
| **Token Lookup**        | Backend hash token ที่ได้รับ แล้วค้นหา session จาก hash ใน DB                            |
| **Session Expiry**      | เวลาหมดอายุของ session; ระบบเราตัดสินจาก `expires_at` ใน DB ที่ 30 นาที                  |
| **Absolute Lifetime**   | อายุ session นับจาก Login แล้วหมดตามเวลาที่กำหนด แม้ผู้ใช้ใช้งานต่อเนื่อง                |
| **Non-sliding Expiry**  | request ปกติไม่ต่อเวลา `expires_at` ออกไป                                                |
| **Revocation**          | การทำให้ session ใช้ไม่ได้ก่อนหมดอายุ โดยตั้ง `is_revoked=true`                          |
## Cookie Security

| คำศัพท์                    | หน้าที่                                                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **HttpOnly**               | JavaScript อ่าน Cookie ไม่ได้ ลดผลกระทบจาก XSS                                                                |
| **Secure**                 | Production ส่ง Cookie ผ่าน HTTPS เท่านั้น                                                                     |
| **SameSite=Strict**        | ลดการส่ง Cookie เมื่อ request มาจากเว็บไซต์อื่น                                                               |
| **Path=/`**                | Cookie ใช้กับ path ภายในเว็บไซต์ตามที่กำหนด                                                                   |
| **Host-only Cookie**       | ไม่กำหนด `Domain` เพื่อไม่ให้ subdomain อื่นรับ Cookie ได้                                                    |
| **Browser-session Cookie** | Cookie ไม่มี `Max-Age`/`Expires`; Browser ควบคุมอายุ แต่ระบบยังใช้ `expires_at` ใน DB เป็นตัวตัดสินจริง       |
| **CSRF**                   | เว็บไซต์อื่นพยายามสั่ง Browser ที่ Login อยู่ทำ action แทนผู้ใช้; จึงต้องตรวจ Origin/Referer และ header เพิ่ม |
## เหตุการณ์และการโจมตีที่ต้องรู้

| คำศัพท์               | ความหมาย                                                                                             |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| **Session Fixation**  | ผู้โจมตีบังคับให้เหยื่อใช้ token ที่ผู้โจมตีรู้ค่า; ป้องกันด้วยการสร้าง token ใหม่ทุกครั้งหลัง Login |
| **Session Hijacking** | ผู้โจมตีขโมย token แล้วสวมรอยเป็นผู้ใช้                                                              |
| **XSS**               | ผู้โจมตีฉีด JavaScript ลงเว็บ; `HttpOnly` ช่วยไม่ให้ script อ่าน Cookie ได้                          |
| **Fail Closed**       | ถ้า Database/session store ใช้งานไม่ได้ ให้ปฏิเสธ protected request ไม่ใช่อนุญาตไปก่อน               |
| **401 Unauthorized**  | ยังยืนยันตัวตนไม่ได้ เช่น ไม่มี Cookie, session หมดอายุ หรือถูก revoke                               |
| **403 Forbidden**     | ยืนยันตัวตนแล้ว แต่ role ไม่มี permission นั้น                                                       |
| **Default Deny**      | ถ้าไม่ได้ระบุว่าอนุญาต ให้ถือว่าไม่อนุญาต                                                            |
## คำที่คนมักสับสน

- **Cookie ไม่ใช่ Session**  
    Cookie เป็น “ช่องทางส่ง token” ส่วน Session คือข้อมูลและสถานะที่ Server เก็บใน `auth_sessions`
    
- **Opaque Token ไม่ใช่ UUID ในตาราง**  
    Token เป็น secret สำหรับ Browser ส่วน UUID เป็น ID ภายใน Database
    
- **Password Hash ไม่ใช่ Session Token Hash**  
    Password ใช้ `Argon2id` เพราะเป็นสิ่งที่มนุษย์เดาได้ จึงต้อง hash แบบช้าและใช้ RAM มาก  
    Session token ใช้ `SHA-256` เพราะ token สุ่ม 256 bits อยู่แล้ว และต้องค้นหาเร็วทุก request
    
- **Logout ไม่ใช่แค่ลบ Cookie**  
    ต้อง revoke row ใน `auth_sessions` ด้วย มิฉะนั้น token ที่ถูกขโมยอาจยังใช้ได้
    

ประโยคที่ควรจำสำหรับตอบอาจารย์:

> Cookie เป็นเพียงซองที่ Browser ส่ง opaque token กลับมา ส่วน session state, user status และ RBAC อยู่ใน Database ฝั่ง Server ซึ่งเป็น Source of Truth ทำให้ MyNetMate revoke session หรือ deactivate user ได้ทันที
