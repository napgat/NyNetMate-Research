## 1. Authentication & RBAC

สถานะ: Design และ Contract พร้อม Implement แล้ว ตาม [Auth update (line 29)](E:/CEPP Project/หลักศูตร/KMITL_Knowledge/Project/02_feature/00_Authentication(Naphat\)/อัพเดทกับอาจารย์ _auth_04_09_2569.md:29)

ลำดับทำ:

1. เพิ่ม Database engine, SQLAlchemy, Alembic และ Argon2id
2. สร้าง Migration ตามลำดับ `users → auth_sessions`
3. ทำ Password Hasher, Dummy Hash และ Login rate limiter
4. ทำ Audit Adapter ที่เรียก Audit Writer กลาง
5. ทำ API ตามลำดับ:
    - `POST /auth/login`
    - `GET /auth/me`
    - `POST /auth/logout`
6. ทำ Session Guard และ `require_permission()` แบบ Default Deny
7. เพิ่ม Origin/CSRF Guard สำหรับคำสั่งที่เปลี่ยนข้อมูล
8. ทำเปลี่ยนรหัสผ่านและ User Management
9. ทำ Frontend API client ด้วย `credentials: "include"`
10. ทำหน้า Login, Session State, Protected Route และ User Management
11. รัน Acceptance Tests และ Demo:
    - Viewer เรียก Admin API ได้ `403`
    - Admin Deactivate Operator
    - Request ถัดไปของ Operator ได้ `401`
    - มี Audit Event ครบ

ยังไม่ควรทำ OAuth, MFA, Forgot Password, LDAP หรือสิทธิ์ระดับรายอุปกรณ์

## 2. Audit Trail

สถานะ: Contract พร้อม แต่ยังไม่มีตาราง, Writer, API และ Test ตาม [Audit update (line 18)](E:/CEPP Project/หลักศูตร/KMITL_Knowledge/Project/02_feature/11_Audit Trail(Naphat\)/อัพเดทกับอาจารย์ _audittrail_04_09_2569.md:18)

แบ่งทำสองช่วง:

ช่วงแรก—ทำก่อน Auth API:

1. สร้าง `audit_logs` Migration หลัง `users`
2. สร้าง Global Action Registry
3. สร้าง `record_audit_event()`
4. ทำ Redaction และ Safe Error Category allowlist
5. บังคับ Append-only
6. ทดสอบ Transaction:
    - Business action สำเร็จพร้อม Audit
    - Audit ล้มเหลวแล้ว Business action ต้อง Rollback
    - Login Failed และ Permission Denied ใช้ Transaction แยกและยัง Commit ได้

ช่วงสอง—ทำหลัง Auth/RBAC ใช้งานได้:

1. ทำ `GET /api/audit-logs`
2. จำกัดเฉพาะ Permission `audit.read` หรือ Admin
3. เพิ่ม Filter และ Cursor Pagination
4. ทำหน้า Full Audit Trail
5. เปิด Recent Activity contract ให้ Dashboard อ่าน
6. ค่อยเพิ่ม Event ของ Device, Config, CIS และ Settings เมื่อเจ้าของ Feature ยืนยัน Flow แล้ว

อย่ากำหนด Event ของ Feature ที่ยังออกแบบไม่จบล่วงหน้า

## 3. Dashboard & Monitoring

สถานะ: ยังเริ่ม Full-stack ไม่ควร เพราะเหลือ Dependency สามจุดตาม [Dashboard update (line 26)](E:/CEPP Project/หลักศูตร/KMITL_Knowledge/Project/02_feature/01_Dashboard&Monitoring(Naphat\)/อัพเดทกับอาจารย์ _d&m_04_09_2569.md:26)

สิ่งที่ต้องทำก่อนเขียนโค้ด:

1. คุยกับ Tee ฝั่ง Device Inventory:
    - `unknown`, `online`, `offline`, `unreachable`, `maintenance`
    - ใช้ `last_seen_at` หรือ `last_collected_at`
    - Device ที่ยังไม่เคยตรวจต้องไม่ถูกนับว่าเสีย
2. คุยกับ King ฝั่ง CIS:
    - Critical นับ Finding หรือ Device
    - ใช้ผล Scan ล่าสุดหรือไม่
    - Finding ที่ Override แล้วยังนับหรือไม่
3. กำหนดเจ้าของ Settings:
    - `offline_mode` เก็บใน Database หรือ `.env`
    - ให้ทุก Feature อ่านจาก Source of Truth เดียวกัน

หลังปิดสามข้อนี้:

1. อัปเดต Dashboard API Contract และ Acceptance Tests
2. ทำ `GET /api/dashboard/summary`
3. ทำ `GET /api/dashboard/recent-activity`
4. ทำ `GET /api/system/health`
5. ทำ Frontend cards, Recent Activity, System Health และ Quick Actions
6. ทดสอบ Unknown/Stale/Offline Mode/RBAC/Redaction
7. วัด Performance กับข้อมูลจำลอง 1,000 อุปกรณ์ก่อนพิจารณา Cache

Dashboard ห้ามสร้างตาราง Device, Security หรือ Audit ซ้ำ และห้ามเรียก Gemini เพื่อคำนวณ Metric
