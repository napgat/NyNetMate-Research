# Use Case Description — MyNetMate Network Management

เอกสารนี้เป็นข้อกำหนดออกแบบสำหรับขอบเขต Network Management โดยไม่รวม Configuration Management การระบุขั้นตอนในเอกสารไม่ใช่การยืนยันว่าทุกหน้าจอและทุก API พัฒนาและทดสอบครบแล้ว

แยกการเข้าสู่ระบบกับการออกจากระบบ และการเพิ่มอุปกรณ์กับการแก้ไขอุปกรณ์เป็นคนละ Use Case เพื่อให้ขั้นตอนและเงื่อนไขชัดเจน

เงื่อนไขร่วม: ยกเว้น UC-01 ผู้ใช้งานต้องเข้าสู่ระบบและมีสิทธิ์ในงานนั้น หาก Session หมดอายุ ระบบให้เข้าสู่ระบบใหม่ หากไม่มีสิทธิ์ ระบบปฏิเสธคำขอ Exception Flow ด้านล่างรวมกรณีผิดปกติและทางเลือกที่ไม่เข้าสู่ผลสำเร็จหลัก

## UC-01 เข้าสู่ระบบ

**Description:** ยืนยันตัวตนเพื่อเข้าใช้งานระบบตามบทบาทที่ได้รับ  
**Actor:** Admin, Operator, Viewer  
**อ้างอิงความต้องการ:** FR-01, FR-02 และ FR-10

**Main Flow**

1. ผู้ใช้งานเปิดหน้าเข้าสู่ระบบ
2. ผู้ใช้งานกรอกชื่อผู้ใช้งานและรหัสผ่าน แล้วกดเข้าสู่ระบบ
3. ระบบตรวจสอบข้อมูลเข้าสู่ระบบและสถานะบัญชี
4. ระบบสร้าง Session และบันทึกเหตุการณ์เข้าสู่ระบบสำเร็จ
5. เมื่อบันทึกสำเร็จ ระบบส่ง Session Cookie และแสดงหน้าหลักตามสิทธิ์

**Exception Flow**

- ขั้นตอนที่ 2: ข้อมูลไม่ครบหรือรูปแบบไม่ถูกต้อง ระบบแจ้งให้แก้ไขข้อมูล
- ขั้นตอนที่ 3: ข้อมูลเข้าสู่ระบบไม่ถูกต้องหรือบัญชีถูกปิดใช้งาน ระบบปฏิเสธการเข้าใช้งานและบันทึกเหตุการณ์ โดยไม่เปิดเผยว่าข้อมูลส่วนใดผิด
- ขั้นตอนที่ 3: มีการพยายามเข้าสู่ระบบจาก IP เดียวเกินขีดจำกัด ระบบแจ้งให้รอก่อนลองใหม่
- ขั้นตอนที่ 4: ไม่สามารถบันทึก Session หรือเหตุการณ์ได้ ระบบไม่อนุญาตให้เข้าสู่ระบบ และแจ้งว่าบริการไม่พร้อมใช้งาน

## UC-02 ออกจากระบบ

**Description:** สิ้นสุดการใช้งานโดยเพิกถอน Session ปัจจุบัน  
**Actor:** Admin, Operator, Viewer  
**อ้างอิงความต้องการ:** FR-01 และ FR-10

**Main Flow**

1. ผู้ใช้งานเลือกออกจากระบบ
2. ระบบตรวจสอบ Session ปัจจุบัน
3. ระบบเพิกถอน Session และบันทึกเหตุการณ์ออกจากระบบ
4. ระบบล้าง Session Cookie และแสดงหน้าเข้าสู่ระบบ

**Exception Flow**

- ขั้นตอนที่ 2: Session ไม่มีอยู่หรือหมดอายุ ระบบแจ้งว่าไม่ได้อยู่ในสถานะเข้าสู่ระบบและให้กลับไปเข้าสู่ระบบ
- ขั้นตอนที่ 3: ไม่สามารถบันทึกการเพิกถอนหรือเหตุการณ์ได้ ระบบแจ้งข้อผิดพลาด โดยไม่ยืนยันว่าเพิกถอน Session สำเร็จ
- ขั้นตอนที่ 4: การเชื่อมต่อขาดหายก่อนรับผล ระบบไม่แสดงผลสำเร็จที่ยังยืนยันไม่ได้ และให้ตรวจสอบสถานะหรือลองใหม่

## UC-03 ดูแดชบอร์ด

**Description:** ดูภาพรวมจำนวนอุปกรณ์และสถานะเครือข่ายจากข้อมูลที่ระบบจัดเก็บ  
**Actor:** Admin, Operator, Viewer  
**อ้างอิงความต้องการ:** FR-06 และ NFR-02

**Main Flow**

1. ผู้ใช้งานเปิดหน้าแดชบอร์ด
2. ระบบอ่านข้อมูลอุปกรณ์และสถานะล่าสุดที่จัดเก็บไว้
3. ระบบสรุปจำนวนอุปกรณ์และจำนวนตามสถานะ
4. ระบบแสดงข้อมูลสรุปพร้อมเวลาที่เก็บหรือตรวจสอบข้อมูล เพื่อให้ผู้ใช้งานทราบความใหม่ของข้อมูล

**Exception Flow**

- ขั้นตอนที่ 2: ยังไม่มีข้อมูลอุปกรณ์ ระบบแสดงสถานะว่างหรือจำนวนศูนย์
- ขั้นตอนที่ 2: ไม่สามารถดึงข้อมูลได้ ระบบแสดงข้อความแจ้งข้อผิดพลาด ไม่แสดงจำนวนศูนย์แทนความล้มเหลว
- ขั้นตอนที่ 4: ข้อมูลบางส่วนยังไม่เคยตรวจสอบหรือเป็นข้อมูลเก่า ระบบระบุเวลาหรือสถานะไม่ทราบให้ชัดเจน

หมายเหตุการพัฒนา: หน้า Home ปัจจุบันยังระบุว่าไม่มี Dashboard Widgets ขั้นตอนข้างต้นจึงเป็นข้อกำหนดออกแบบ ไม่ใช่ผลการทดสอบแดชบอร์ดที่เสร็จแล้ว

## UC-04 ดูรายการและรายละเอียดอุปกรณ์

**Description:** ค้นหาและดูข้อมูลอุปกรณ์ที่อยู่ในทะเบียน รวมถึงข้อมูล Interface และสถานะที่จัดเก็บไว้  
**Actor:** Admin, Operator, Viewer  
**อ้างอิงความต้องการ:** FR-04 และ NFR-02

**Main Flow**

1. ผู้ใช้งานเปิดหน้าทะเบียนอุปกรณ์
2. ระบบอ่านข้อมูลและแสดงรายการอุปกรณ์
3. ผู้ใช้งานระบุคำค้นหาหรือตัวกรองตามต้องการ
4. ระบบแสดงรายการที่ตรงกับเงื่อนไข
5. ผู้ใช้งานเลือกอุปกรณ์ แล้วระบบแสดงรายละเอียด Interface สถานะ และเวลาที่เก็บข้อมูล

**Exception Flow**

- ขั้นตอนที่ 2 หรือ 4: ไม่พบข้อมูลตามเงื่อนไข ระบบแสดงข้อความว่าไม่พบอุปกรณ์
- ขั้นตอนที่ 5: อุปกรณ์ที่เลือกไม่มีอยู่แล้ว ระบบแจ้งว่าไม่พบข้อมูลและให้โหลดรายการใหม่
- ขั้นตอนที่ 2, 4 หรือ 5: ไม่สามารถดึงข้อมูลได้ ระบบแจ้งข้อผิดพลาดโดยไม่สรุปว่าทะเบียนไม่มีอุปกรณ์

## UC-05 ดูแผนผังเครือข่ายและรายละเอียดบนแผนผัง

**Description:** ดูความสัมพันธ์ระหว่างอุปกรณ์จากข้อมูลและหลักฐานที่จัดเก็บไว้ พร้อมเลือกอุปกรณ์เพื่อดูรายละเอียด  
**Actor:** Admin, Operator, Viewer  
**อ้างอิงความต้องการ:** FR-08, FR-09 และ NFR-02

**Main Flow**

1. ผู้ใช้งานเปิดหน้าแผนผังเครือข่าย
2. ระบบอ่านข้อมูลอุปกรณ์และหลักฐานความสัมพันธ์
3. ระบบแสดงอุปกรณ์เป็นจุดและแสดงความสัมพันธ์ที่มีหลักฐานรองรับเป็นเส้นเชื่อม
4. ผู้ใช้งานเลือกอุปกรณ์บนแผนผัง
5. ระบบแสดงรายละเอียดอุปกรณ์และข้อมูลที่เกี่ยวข้อง

**Exception Flow**

- ขั้นตอนที่ 2: ยังไม่มีข้อมูลอุปกรณ์ ระบบแสดงแผนผังว่างพร้อมข้อความแนะนำ
- ขั้นตอนที่ 3: มีอุปกรณ์แต่ไม่มีหลักฐานความสัมพันธ์ ระบบแสดงอุปกรณ์โดยไม่สร้างเส้นเชื่อมขึ้นเอง
- ขั้นตอนที่ 5: จุดที่เลือกเป็นอุปกรณ์ที่ยังไม่ลงทะเบียนหรือเป็นโหนดภายนอก ระบบแสดงเฉพาะข้อมูลที่มี ไม่แสดงรายละเอียดที่ไม่มีหลักฐาน
- ขั้นตอนที่ 2 หรือ 5: ไม่สามารถดึงข้อมูลได้ ระบบแจ้งข้อผิดพลาด

## UC-06 เพิ่มอุปกรณ์เข้าทะเบียน

**Description:** เพิ่มอุปกรณ์โดยระบุข้อมูลเชื่อมต่อและรวบรวมข้อมูลที่จำเป็นผ่าน SNMP ก่อนบันทึกลงทะเบียน  
**Actor:** Admin, Operator  
**อ้างอิงความต้องการ:** FR-03, FR-10, NFR-03 และ NFR-04

**Main Flow**

1. ผู้ใช้งานเลือกเพิ่มอุปกรณ์ แล้วระบบแสดงแบบฟอร์ม
2. ผู้ใช้งานระบุ IP Address โปรไฟล์ข้อมูลสำหรับเชื่อมต่อ และข้อมูลประกอบ แล้วกดยืนยัน
3. ระบบตรวจสอบข้อมูล โปรไฟล์เชื่อมต่อ และความซ้ำของ IP Address
4. ระบบอ่านข้อมูลอุปกรณ์และ Interface ผ่าน SNMP ภายในสภาพแวดล้อมทดสอบ
5. ระบบตรวจสอบข้อมูลที่จำเป็นและตัวตนอุปกรณ์ว่าไม่ซ้ำ แล้วบันทึกอุปกรณ์ Interface และผลการรวบรวม
6. ระบบปรับปรุงรายการอุปกรณ์และแจ้งผลสำเร็จ

**Exception Flow**

- ขั้นตอนที่ 3: ข้อมูลไม่ถูกต้อง โปรไฟล์ไม่พร้อมใช้งาน หรือ IP มีในทะเบียนแล้ว ระบบปฏิเสธการเพิ่มและแจ้งสาเหตุที่เหมาะสม
- ขั้นตอนที่ 4 หรือ 5: ติดต่ออุปกรณ์ไม่ได้ ข้อมูลที่จำเป็นไม่ครบ หรือพบตัวตนอุปกรณ์ซ้ำ ระบบไม่เพิ่มอุปกรณ์ใหม่ และเก็บผลการรวบรวมที่ได้เริ่มดำเนินการแล้ว
- ขั้นตอนที่ 5: บันทึกไม่สำเร็จ ระบบไม่แสดงผลว่าเพิ่มอุปกรณ์สำเร็จ และแจ้งข้อผิดพลาด

## UC-07 แก้ไขข้อมูลอุปกรณ์ในทะเบียน

**Description:** ปรับปรุงข้อมูลประกอบอุปกรณ์ในทะเบียน เช่น บทบาท กลุ่ม สถานที่ หมายเหตุ หรือโปรไฟล์เชื่อมต่อ โดยไม่เปลี่ยน Configuration บนอุปกรณ์  
**Actor:** Admin, Operator  
**อ้างอิงความต้องการ:** FR-03 และ FR-10

**Main Flow**

1. ผู้ใช้งานเลือกอุปกรณ์ที่ต้องการแก้ไขจากทะเบียน
2. ระบบแสดงข้อมูลเดิมและแบบฟอร์มแก้ไข
3. ผู้ใช้งานปรับปรุงข้อมูลที่อนุญาตให้แก้ไข แล้วกดบันทึก
4. ระบบตรวจสอบข้อมูลและข้อมูลอ้างอิง เช่น กลุ่ม สถานที่ และโปรไฟล์เชื่อมต่อ
5. ระบบบันทึกการเปลี่ยนแปลงลงฐานข้อมูล
6. ระบบแสดงข้อมูลล่าสุดและแจ้งผลสำเร็จ

**Exception Flow**

- ขั้นตอนที่ 2: ไม่พบอุปกรณ์ ระบบแจ้งข้อผิดพลาดและให้กลับไปเลือกจากรายการ
- ขั้นตอนที่ 4: ข้อมูลไม่ถูกต้องหรือข้อมูลอ้างอิงไม่มีอยู่ ระบบไม่บันทึกและแจ้งให้แก้ไข
- ขั้นตอนที่ 5: ไม่สามารถบันทึกได้ ระบบแจ้งข้อผิดพลาดและไม่แสดงผลสำเร็จ

## UC-08 สั่งค้นหาอุปกรณ์เครือข่าย

**Description:** ค้นหาและรวบรวมข้อมูลจากอุปกรณ์เริ่มต้น เพื่อจัดเก็บอุปกรณ์และหลักฐานความสัมพันธ์สำหรับสร้างแผนผัง  
**Actor:** Admin, Operator  
**อ้างอิงความต้องการ:** FR-05, FR-08, FR-10 และ NFR-04

**Main Flow**

1. ผู้ใช้งานเลือกค้นหาอุปกรณ์ แล้วระบบแสดงแบบฟอร์ม
2. ผู้ใช้งานระบุ IP Address ของอุปกรณ์เริ่มต้น โปรไฟล์เชื่อมต่อ และขอบเขตการค้นหา แล้วเริ่มค้นหา
3. ระบบตรวจสอบข้อมูลและโปรไฟล์เชื่อมต่อ
4. ระบบเรียก Network Discovery Library และรวบรวมข้อมูลผ่าน SNMP ภายในสภาพแวดล้อมทดสอบ โดยจัดเก็บข้อมูลที่รวบรวมสำเร็จ
5. เมื่อค้นหาได้ตามขอบเขต ระบบบันทึกผลสำเร็จและข้อมูลความสัมพันธ์ที่มีหลักฐานรองรับ
6. ระบบแสดงแผนผังเครือข่ายและผลการค้นหา

**Exception Flow**

- ขั้นตอนที่ 3: ข้อมูลหรือโปรไฟล์ไม่ถูกต้อง ระบบไม่เริ่มค้นหาและแจ้งให้แก้ไข
- ขั้นตอนที่ 4: รวบรวมได้บางส่วนหรือถึงขีดจำกัด ระบบเก็บข้อมูลที่สำเร็จ บันทึกผลได้บางส่วน และแสดงแผนผังจากหลักฐานที่มี
- ขั้นตอนที่ 4: ไม่สามารถรวบรวมข้อมูลที่จำเป็นได้ ระบบบันทึกผลล้มเหลวและแจ้งข้อผิดพลาด โดยไม่ลบข้อมูลอุปกรณ์เดิม
- ขั้นตอนที่ 4 หรือ 5: การค้นหาถูกยกเลิกหรือขัดจังหวะ ระบบเก็บข้อมูลและประวัติที่บันทึกสำเร็จแล้ว โดยไม่รายงานว่าค้นหาครบถ้วน

## UC-09 สั่งอัปเดตข้อมูลสถานะอุปกรณ์

**Description:** ตรวจสอบการติดต่ออุปกรณ์ที่ลงทะเบียน แล้วจัดเก็บผลสถานะและเวลาที่ตรวจสอบล่าสุด โดยไม่หมายถึงการรวบรวมข้อมูลอุปกรณ์ทุกส่วนใหม่  
**Actor:** Admin, Operator  
**อ้างอิงความต้องการ:** FR-07 และ NFR-02

**Main Flow**

1. ผู้ใช้งานเลือกอุปกรณ์หรือกลุ่มเป้าหมายที่ต้องการตรวจสอบสถานะ
2. ผู้ใช้งานสั่งอัปเดตสถานะ
3. ระบบตรวจสอบอุปกรณ์เป้าหมายและโปรไฟล์เชื่อมต่อ
4. ระบบตรวจสอบการตอบสนองของอุปกรณ์ผ่าน SNMP ภายในสภาพแวดล้อมทดสอบ
5. ระบบบันทึกสถานะการติดต่อและเวลาที่ตรวจสอบ
6. ระบบแสดงสถานะล่าสุดพร้อมสรุปผลการตรวจสอบ

**Exception Flow**

- ขั้นตอนที่ 3: ไม่พบอุปกรณ์ ระบบแจ้งว่าไม่พบเป้าหมาย
- ขั้นตอนที่ 3 หรือ 4: ไม่มีโปรไฟล์ที่ใช้ได้หรือเริ่มตรวจสอบไม่ได้ ระบบแสดงสถานะไม่ทราบพร้อมสาเหตุที่เหมาะสม
- ขั้นตอนที่ 4: อุปกรณ์ไม่ตอบสนอง ระบบรายงานผลการติดต่อที่ตรวจพบ ไม่สรุปว่าอุปกรณ์เสียโดยอัตโนมัติ
- ขั้นตอนที่ 4: บางอุปกรณ์ตรวจสอบไม่สำเร็จ ระบบแสดงผลแยกรายอุปกรณ์ ไม่เปลี่ยนทุกอุปกรณ์เป็นสถานะเดียวกัน
- ขั้นตอนที่ 5: บันทึกไม่สำเร็จ ระบบแจ้งข้อผิดพลาดและไม่ยืนยันว่าปรับปรุงสถานะในฐานข้อมูลแล้ว

## UC-10 จัดการผู้ใช้งาน

**Description:** เพิ่มบัญชี กำหนดบทบาท และเปิดหรือปิดการใช้งานบัญชีผู้ใช้งาน  
**Actor:** Admin  
**อ้างอิงความต้องการ:** FR-11, FR-02, FR-10 และ NFR-01

**Main Flow**

1. Admin เปิดหน้าจัดการผู้ใช้งาน
2. ระบบตรวจสอบสิทธิ์และแสดงรายการบัญชี
3. Admin เลือกเพิ่มบัญชี หรือเลือกบัญชีเดิมเพื่อเปลี่ยนบทบาทหรือสถานะใช้งาน
4. Admin กรอกข้อมูลที่เกี่ยวข้องแล้วกดยืนยัน
5. ระบบตรวจสอบความถูกต้อง ความซ้ำของบัญชีใหม่ และเงื่อนไขคงเหลือ Admin ที่ใช้งานได้อย่างน้อยหนึ่งบัญชี
6. ระบบบันทึกข้อมูลและเหตุการณ์ โดยเพิกถอน Session ของบัญชีที่เปลี่ยนบทบาทหรือถูกปิดใช้งาน
7. ระบบปรับปรุงรายการและแจ้งผลสำเร็จ

**Exception Flow**

- ขั้นตอนที่ 2: ผู้ใช้งานไม่ใช่ Admin หรือสิทธิ์เปลี่ยนระหว่างดำเนินการ ระบบปฏิเสธคำขอ
- ขั้นตอนที่ 5: ข้อมูลไม่ถูกต้องหรือชื่อผู้ใช้งานหรืออีเมลซ้ำ ระบบไม่เพิ่มบัญชีและแจ้งให้แก้ไข
- ขั้นตอนที่ 5: ไม่พบบัญชีเป้าหมาย ระบบแจ้งข้อผิดพลาด
- ขั้นตอนที่ 5: การเปลี่ยนแปลงจะทำให้ไม่มี Admin ที่ใช้งานได้ ระบบปฏิเสธการเปลี่ยนแปลง
- ขั้นตอนที่ 6: บันทึกข้อมูลหรือเหตุการณ์ไม่สำเร็จ ระบบไม่ยืนยันผลสำเร็จและไม่บันทึกการเปลี่ยนแปลงบางส่วน

## UC-11 ดูประวัติเหตุการณ์

**Description:** ตรวจสอบประวัติเหตุการณ์ย้อนหลัง โดยดูผู้ดำเนินการเมื่อระบุตัวตนได้ การกระทำ ผลลัพธ์ และเวลาที่เกิดเหตุการณ์  
**Actor:** Admin  
**อ้างอิงความต้องการ:** FR-12, FR-10 และ NFR-01

**Main Flow**

1. Admin เปิดหน้าประวัติเหตุการณ์
2. ระบบตรวจสอบสิทธิ์ในการดูประวัติ
3. Admin กำหนดตัวกรองตามต้องการ เช่น ช่วงเวลา ประเภทการกระทำ ผู้ดำเนินการ หรือผลลัพธ์
4. ระบบอ่านประวัติที่ตรงกับเงื่อนไขและแสดงเป็นรายการแบ่งหน้า
5. Admin ตรวจสอบรายละเอียดหรือเปิดหน้าถัดไป โดยไม่สามารถแก้ไขประวัติผ่านการดูรายการนี้

**Exception Flow**

- ขั้นตอนที่ 2: ไม่มีสิทธิ์หรือ Session ใช้ไม่ได้ ระบบปฏิเสธการเข้าถึง
- ขั้นตอนที่ 3: ตัวกรองไม่ถูกต้อง เช่น เวลาเริ่มต้นอยู่หลังเวลาสิ้นสุด ระบบแจ้งให้แก้ไข
- ขั้นตอนที่ 4: ไม่มีรายการที่ตรงกับเงื่อนไข ระบบแสดงข้อความว่าไม่พบประวัติ
- ขั้นตอนที่ 4 หรือ 5: อ่านข้อมูลไม่ได้ ระบบแจ้งข้อผิดพลาดโดยไม่แสดงข้อมูลลับ เช่น รหัสผ่านหรือ Token

## หมายเหตุสำหรับการนำไปใช้ในรายงาน

- FR-11 และ FR-12 เป็นข้อกำหนดที่เสนอให้เพิ่มในตาราง 3.1 ต้องตรวจว่ารหัสและข้อความในรายงานฉบับล่าสุดตรงกัน
- การบันทึกเหตุการณ์ตาม FR-10 เป็นพฤติกรรมของระบบ ไม่ใช่ Use Case ที่ผู้ใช้ต้องกดบันทึกเอง งานจัดการอุปกรณ์และค้นหาเครือข่ายควรมีการบันทึกตามข้อกำหนด แต่เอกสารนี้ไม่ได้ยืนยันว่าการเชื่อม Audit ครบทุกเส้นทางแล้ว
- Actor ของงานค้นหาและอัปเดตสถานะเป็นการจัดสรรสิทธิ์ในแบบออกแบบ ต้องตรวจการบังคับสิทธิ์ของ API ให้ครบก่อนกล่าวว่า Implemented
- UC-09 หมายถึงตรวจสอบสถานะการติดต่อ ไม่ใช่การค้นหาเครือข่ายหรือเปลี่ยน Configuration
- ภาพ Use Case ควรใช้ชื่อและการแยกกิจกรรมให้ตรงกับเอกสารนี้ หากคงวงรีแบบรวม เช่น “จัดการทะเบียนอุปกรณ์” ต้องระบุว่าครอบคลุม UC-06 และ UC-07
