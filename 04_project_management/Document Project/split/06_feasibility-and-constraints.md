## **5. ความเป็นไปได้และข้อจำกัด (Feasibility & Constraints)** 

การวิเคราะห์ความเป็นไปได้และข้อจำกัดของโครงงาน ประกอบด้วย 3 ส่วนหลัก ดังนี้ 

- **5.1. ทางเลือกและการคัดเลือก (Alternatives and Selection)** 

- ในการดำเนินโครงงานเพื่อให้ได้ระบบที่มีประสิทธิภาพและตอบโจทย์ความต้องการของผู้ใช้งานมาก 

- ที่สุด คณะผู้จัดทำได้รวบรวมข้อมูลและวิเคราะห์แนวทางการแก้ปัญหา โดยแบ่งออกเป็น 3 ทางเลือกหลัก 

   - 1) ทางเลือกที่ 1: การจัดการแบบดั้งเดิม (Manual Configuration & Documentation) ผู้ดูแล ระบบเชื่อมต่อผ่านโปรโตคอล SSH เพื่อแก้ไขอุปกรณ์ทีละเครื่อง และบันทึกข้อมูลลงใน ซอฟต์แวร์สเปรดชีต 

   - 2) ทางเลือกที่ 2: ซอฟต์แวร์บริหารจัดการเครือข่ายสำเร็จรูป (Commercial Network Management Software) การใช้เครื่องมือระดับองค์กรที่มีวางจำหน่ายในท้องตลาด ซึ่งมีความ เสถียรสูงแต่มีข้อจำกัดด้านค่าใช้จ่ายที่สูงมาก เหมาะสำหรับองค์กรขนาดใหญ่เท่านั้น 

   - 3) ทางเลือกที่ 3: ระบบอัตโนมัติแบบผสมผสาน (Hybrid AI-Powered Automation System) แนวทางที่โครงงานนี้เสนอ โดยผสานความแม่นยำของระบบแม่แบบ (ร้อยละ 80) เข้ากับความ ยืดหยุ่นของปัญญาประดิษฐ์แบบรู้สร้าง (ร้อยละ 20) เพื่อให้ได้ระบบที่มีประสิทธิภาพสูงใน ต้นทุนที่เหมาะสม 

เพื่อให้การตัดสินใจเป็นไปตามหลักวิศวกรรม คณะผู้จัดทำได้ใช้ตารางประเมินการตัดสินใจแบบถ่วง น้ำหนัก (Weighted Decision Matrix - WDM) โดยกำหนดน้ำหนักของเกณฑ์การวัดตามระดับความสำคัญ ที่สกัดได้จากเสียงของลูกค้า (Voice of the Customer) และเป้าหมายเชิงปริมาณ (QRs)

## **5.2. ข้อจำกัดที่สมจริง (Realistic Constraints)** 

ในการพัฒนาระบบบริหารจัดการเครือข่ายอัตโนมัติ คณะผู้จัดทำได้พิจารณาถึงข้อจำกัดในโลกความ เป็นจริงที่อาจส่งผลกระทบต่อการนำระบบไปใช้งานจริงในองค์กร  ดังนี้ 

- 1) ด้านเศรษฐศาสตร์ (Economic Constraints): ระบบมีการผสานการทำงานกับ Google Gemini API เพื่อสร้างชุดคำสั่งและรายงาน ซึ่งมีต้นทุนแฝงตามปริมาณการใช้งาน (Token Usage) คณะผู้จัดทำจึงบริหารความเสี่ยงนี้โดยใช้สถาปัตยกรรมแบบ Hybrid ที่ยึดระบบ แม่แบบ (Template) เป็นโครงสร้างหลัก เพื่อลดการคำนวณของ AI โดยไม่จำเป็น ทำให้องค์กร สามารถควบคุมงบประมาณค่าใช้จ่าย API ได้อย่างมีประสิทธิภาพ  [6] 

- 2) ด้านความปลอดภัยและจริยธรรม (Security, Privacy & Ethics): เนื่องจากระบบต้องส่งข้อมูล บางส่วนไปประมวลผลผ่าน Public LLM API จึงเสี่ยงต่อการรั่วไหลของข้อมูลละเอียดอ่อน โครงงานนี้จึงมีข้อจำกัดที่ต้องพัฒนาระบบปกป้องข้อมูลส่วนบุคคล (PII Protection) เพื่อคัด กรองรหัสผ่านและหมายเลขไอพีก่อนส่งข้อมูลออกสู่ภายนอก เพื่อให้สอดคล้องกับกฎหมาย คุ้มครองข้อมูลส่วนบุคคล (PDPA) อย่างเคร่งครัด [7] 

## **5.3. การวิเคราะห์คุณค่า (Value Proposition)**
