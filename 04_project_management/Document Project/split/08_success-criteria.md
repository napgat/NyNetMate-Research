## **7. เกณฑ์การประเมินความสำเร็จ (Success Criteria)** 

เพื่อให้มั่นใจว่าระบบสามารถทำงานได้ตามข้อกำหนดเชิงปริมาณ (QRs) และตอบสนองความต้องการของ ผู้ใช้งานได้อย่างมีประสิทธิภาพ คณะผู้จัดทำจึงกำหนดเกณฑ์ความสำเร็จเชิงวิศวกรรมโดยแบ่งออกเป็นมิติต่างๆ ดังนี้ 

## **7.1. การพิสูจน์ความถูกต้องทางสถิติ (Statistical Validation)** 

เนื่องจากระบบใช้สถาปัตยกรรม Hybrid AI (Template 80% + AI พร้อม RAG 20%) ความถูกต้อง ของผลลัพธ์จึงต้องได้รับการพิสูจน์ด้วยวิธีการทางสถิติ ดังนี้ 

1) เกณฑ์ที่ 1: ความถูกต้องของการสร้างชุดคำสั่ง (Configuration Accuracy) 

ใช้ชุดข้อมูลทดสอบ 100 ไฟล์ ครอบคลุมสถานการณ์ VLAN, ACL และ Routing บนอุปกรณ์ Cisco และ MikroTik โดยประเมินโดยผู้เชี่ยวชาญ 

**==> picture [203 x 29] intentionally omitted <==**

เกณฑ์ผ่าน **:** Accuracy ≥ 95% และไม่พบข้อผิดพลาดร้ายแรง (Critical Syntax Error) แม้ เพียงรายการเดียว 

2) เกณฑ์ที่ 2: อัตราการแจ้งเตือนผิดพลาด (False Positive Rate - QR-4) 

**==> picture [222 x 28] intentionally omitted <==**

เกณฑ์ผ่าน: FPR ≤ 5%  และต้องไม่เกิด False Negative ในความปลอดภัยระดับวิกฤต 

## **7.2. การบูรณาการระบบและประสิทธิภาพการตอบสนอง (End-to-End Integration & Latency)** 

ตรวจสอบความหน่วงในจุดวัดสำคัญ (Measurement Point) โดยรายงานค่า Percentile ที่ 95 (p95) จากการทดสอบซ้ำ  ≥ 30ครั้ง 

**ตารางที่  9** เกณฑ์การวัดประสิทธิภาพความหน่วงของระบบ 

|**จดวด (Measurement Point)**|**เปาหมาย**|**QR อางอง**|
|---|---|---|
|API Response Time (ไมรวม LLM)|< 500 ms|ตารางท 4|
|Config Generation (End-to-End รวม LLM)|≤ 30 sec (p95)|QR-1|
|Version Save Latency|≤ 2 sec (p95)|QR-5|
|Diff Render Time|≤ 3 sec (p95)|QR-6|
|Frontend Initial Load|< 2 sec|ตารางท 4|



1) **การทดสอบภายใต้ภาระงาน (Load Test):** จำลองผู้ใช้งานพร้อมกัน 10 ราย (Concurrent Users) โดยมีเกณฑ์ผ่านคือไม่มี Request ใดได้รับ Error 5xx และระบบต้องมี Throughput ≥ 0.33 req/sec

## **7.3. ความทนทานของโมดูลและการบันทึกประวัติ (Robustness & Audit Trail)** 

Code Coverage: ความครอบคลุมของการทดสอบชุดคำสั่งในส่วน Backend และ Frontend ต้อง มีค่า ≥ 80% 

Audit Trail Completeness: บันทึกประวัติกิจกรรมในรูปแบบ Who/When/What ต้องมีความ สมบูรณ์ร้อยละ 100 (Audit Completeness = 100%) สำหรับทุกการกระทำสำคัญในระบบ เช่น การสร้าง Config, การ Deploy และการย้อนกลับสถานะ (Rollback) 

## **7.4. ผลสำเร็จเชิงการใช้งานจริง (Operational Success)** 

User Satisfaction (QR-8) ประเมินจากผู้ใช้งาน 3 กลุ่มหลัก รวม ≥ 5 ท่าน ผ่านแบบประเมิน Likert Scale 1-5 โดยมีเกณฑ์ผ่านคือคะแนนเฉลี่ยรวม ≥ 4.0/5.0 

Time Reduction Validation: พิสูจน์ว่าระบบสามารถลดเวลาการทำงานจริงในขั้นตอนได้ตาม
