ตี๋ ขอถามรายละเอียดฝั่ง Device Inventory หน่อยงับ พอดีผมกำลังล็อกขอบเขต Dashboard & Monitoring P1 รวมถึง API Contract และ Acceptance Test

Dashboard จะไม่ได้สร้างสถานะอุปกรณ์เอง แต่จะอ่านข้อมูลจาก Device Inventory ซึ่งเป็นเจ้าของข้อมูลโดยตรง เลยอยากให้ช่วยยืนยันเรื่องต่อไปนี้หน่อย

1. ความหมายของ `online`, `offline` และ `unreachable`

ตอนนี้ผมยังไม่แน่ใจว่าแต่ละสถานะของตี๋หมายถึงอะไร เช่น

- `online` หมายถึง Ping ล่าสุดสำเร็จ หรือหมายถึงเก็บข้อมูลจากอุปกรณ์สำเร็จด้วย
- `offline` หมายถึง Ping ไม่ตอบ หรือหมายถึงผู้ใช้ตั้งใจปิดใช้งานอุปกรณ์
- `unreachable` หมายถึง Ping ไม่ถึง, SSH เข้าไม่ได้ หรือเก็บข้อมูลไม่ได้

อยากให้ช่วยกำหนดเงื่อนไขของแต่ละสถานะให้ชัด เพราะ Dashboard ต้องนับจำนวนอุปกรณ์ในแต่ละสถานะ ถ้าความหมายไม่ตรงกัน ตัวเลขบน Dashboard อาจทำให้ผู้ใช้เข้าใจผิดได้

2. อุปกรณ์ที่เพิ่งเพิ่มและยังไม่เคยตรวจควรใช้สถานะอะไร

ตัวอย่างเช่น ผู้ใช้เพิ่ง Manual Enroll อุปกรณ์ แต่ระบบยังไม่เคย Ping หรือ Collection เลย กรณีนี้ควรเป็น:

- `unknown`
- `pending`
- `not_checked`
- หรือใช้สถานะอื่น

ผมคิดว่าไม่ควรนับเป็น `offline` ทันที เพราะเรายังไม่มีหลักฐานว่าอุปกรณ์เสีย แค่ยังไม่เคยตรวจ อยากให้ตี๋ช่วยยืนยันชื่อสถานะและเงื่อนไขของกรณีนี้ครับ

3. สถานะ `maintenance` ใครเป็นคนตั้ง

อยากทราบว่า `maintenance` เป็น:

- สถานะที่ Admin/Operator ตั้งเอง
- สถานะที่ระบบตั้งให้อัตโนมัติ
- หรือยังไม่มีใน P1

ถ้ามี อยากทราบด้วยว่าเก็บไว้ใน Field ไหน ใครมีสิทธิ์เปลี่ยน และอุปกรณ์ที่อยู่ระหว่าง Maintenance ควรถูกตัดออกจากจำนวน Offline/Unreachable บน Dashboard หรือไม่

ตัวอย่างเช่น อุปกรณ์ถูกปิดเพื่อซ่อมตามแผน Dashboard ควรแสดงเป็น Maintenance แยกต่างหาก ไม่ควรแจ้งเหมือนเป็นเหตุขัดข้องหรือเปล่าครับ

4. Dashboard ควรใช้ `last_seen_at` หรือ `last_collected_at`

ผมเข้าใจเบื้องต้นว่า:

- `last_seen_at` คือเวลาล่าสุดที่ตรวจพบว่าอุปกรณ์ยังติดต่อได้ เช่น Ping สำเร็จ
- `last_collected_at` คือเวลาล่าสุดที่ระบบเก็บรายละเอียดจากอุปกรณ์สำเร็จ เช่น Interface, VLAN หรือข้อมูลระบบ

อยากให้ตี๋ยืนยันว่าความหมายจริงตรงนี้หรือไม่ และ Dashboard P1 ที่แสดงคำว่า “ตรวจสอบล่าสุด” ควรใช้ค่าไหน

ถ้าจำเป็นต้องใช้ทั้งสองค่า อาจแยกแสดงเป็น:

- ติดต่อได้ล่าสุด: `last_seen_at`
- เก็บข้อมูลสำเร็จล่าสุด: `last_collected_at`

รวมถึงอยากทราบว่าถ้าค่าเก่าเกินระยะเวลาที่กำหนด จะเปลี่ยนสถานะเป็น `stale` หรือแค่แสดงคำเตือนว่าข้อมูลเก่าครับ

5. P1 รองรับการกรองตาม Site หรือ Group หรือไม่

Dashboard จำเป็นต้องรู้ว่าใน P1 จะสามารถดูตัวเลขแบบ:

- ทุกอุปกรณ์รวมกัน
- แยกตาม Site
- แยกตาม Device Group

ได้หรือไม่

ถ้ารองรับ อยากทราบว่า Device Inventory มี `site_id`, `group_id` หรือความสัมพันธ์แบบไหน และ Dashboard ควรส่ง Parameter อะไรไปกรอง เช่น:

```text
GET /api/dashboard/summary?site_id=...
GET /api/dashboard/summary?group_id=...
```

แต่ถ้ายังไม่รองรับใน P1 ผมจะล็อก Dashboard ให้แสดงภาพรวมทั้งหมดก่อน และย้ายการกรอง Site/Group ไป P2 เพื่อไม่ให้ Scope ขยายครับ

6. เอกสารหรือ Schema ไหนเป็นฉบับยืนยัน

ขอชื่อไฟล์หรือ Link ของเอกสารที่ตี๋ต้องการให้ผมใช้อ้างอิงเป็น Source of Truth หน่อยครับ โดยเฉพาะ:

- ชื่อตาราง Device
- ชื่อ Field สถานะ
- ค่าที่อนุญาตของสถานะ
- Field เวลาตรวจล่าสุด
- ความสัมพันธ์กับ Site/Group
- API หรือ Service ที่ Dashboard ใช้อ่านข้อมูล

ถ้ายังไม่มีฉบับ Final สามารถส่งฉบับล่าสุดมาก่อนได้ แล้วระบุส่วนที่ยัง Pending ไว้ก็ได้ครับ ผมจะได้ไม่อ้างชื่อ Field หรือสถานะที่ตี๋ไม่ได้ใช้จริง

ถ้าสะดวก ช่วยตอบสั้น ๆ ตามหัวข้อนี้ก็ได้งับ:

```text
1. online =
   offline =
   unreachable =

2. ยังไม่เคยตรวจ =

3. maintenance =
   ผู้ตั้ง =
   นับรวมใน offline หรือไม่ =

4. last_seen_at =
   last_collected_at =
   Dashboard ควรใช้ =

5. Site/Group filter ใน P1 =
   Field หรือ API ที่ใช้ =

6. เอกสาร/Schema ฉบับยืนยัน =
```

พอได้คำตอบ ผมจะนำไปล็อก Dashboard P1, API Contract และ Acceptance Test ให้ตรงกับ Device Inventory โดยจะไม่สร้างสถานะหรือข้อมูลซ้ำเองครับ
