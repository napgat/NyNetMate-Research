ดังนั้น
ปัญหาใหญ่ที่สุดคือ ตอนนี้ระบบรายวิชาถือเป็น “2 กลุ่มทางการ” แต่ขอบเขตงานและสถาปัตยกรรมยังคิดแบบทีม 4 คนทำระบบเดียว หากไม่จัดใหม่จะกระทบทั้งรายงาน คะแนน และการรวมระบบ

1. **ยังไม่ระบุว่า `(1)` และ `(2)` คือกลุ่มใด**
    
    สมาชิกชัดแล้วว่า:
    
    - Network Management `(1)` = 67015069, 67015026
    - Configuration Automation`(2)` = 67015052, 67015022
    
2. **รายงานสองเล่มอาจกลายเป็นเนื้อหาซ้ำกัน**
    
    ไม่ควรนำรายงานเดิมมาคัดลอกแล้วเปลี่ยนสมาชิก เพราะกรรมการจะแยกไม่ได้ว่าแต่ละกลุ่มทำอะไร ต้องแยก Objective, Scope, Diagram, Schema, การทดสอบ และเปอร์เซ็นต์ความคืบหน้าให้เป็นของแต่ละกลุ่ม
    
3. **Shared Core ยังไม่มีเจ้าของ**
    
    ทั้งสองกลุ่มต้องใช้ข้อมูลร่วมกัน เช่น:
    
    - Device และ Interface
    - Authentication/RBAC
    - Credential
    - Audit Trail
    - Vendor/Platform
    
    หากไม่กำหนด Owner จะเกิดตารางซ้ำ Schema ชนกัน และแก้ข้อมูลคนละความหมาย
    
4. **Configuration Automation จะติดรอกลุ่ม Network Management**
    
    Configuration ต้องใช้ Device ID, Vendor, Model, OS และ Platform จาก Device Inventory หาก Inventory ยังไม่เสร็จ อีกกลุ่มจะพัฒนาและทดสอบไม่ได้ จึงต้องมี Data Contract และ Mock Data ให้ทำงานแยกกันได้
    
5. **ขอบเขตใหญ่เกินสำหรับกลุ่มละ 2 คน**
    
    ขอบเขตขั้นต่ำที่เหมาะกว่า:
    
    - Network Management:
	    - Dashbaord
	    - Device Inventory Management
		    *  Manual Device Enrollment
		    -  Network Discrovery
	    - Network Topology Visualization
	
    - Configuration Automation: 
	    - Configuration Managment
	    - Version Control 
	    - AI Component
		    - PII Sensitive Data Masking
		- Security Validation
		- Configuration Deployment
	
	   * Auth, Credential และ Audit เป็น Shared Core:
		- Network Management อาจเป็นเจ้าของ Auth
		- Configuration Automation อาจเป็นเจ้าของ Audit
		- แต่ทั้งสองกลุ่มต้องใช้ผ่าน Contract ร่วมกัน
		- Credential ต้องกำหนดเจ้าของให้ชัด

1. **Vendor ที่ระบบรับรอง**
    
    ขอบเขตการทดสอบอุปกรณ์หลายผู้ผลิต
	อาจารย์มีอุปกรณ์ Huawei, MikroTik, Dell และ Cisco ให้ยืมทดสอบจริง อย่างไรก็ตาม การมีอุปกรณ์ทดสอบไม่ได้หมายความว่าระบบรองรับทุกความสามารถของทุกผู้ผลิต โดยกำหนดให้ Cisco IOS เป็น Baseline หลัก ส่วน Huawei, MikroTik และ Dell เป็น Candidate Test Vendors ซึ่งจะระบุความสามารถที่รองรับตามรุ่น ระบบปฏิบัติการ ชุดคำสั่ง และผลการทดสอบจริงใน Isolated Lab

    
2. **คำว่า `1 VLAN : 1 Subnet` กำกวม**
    
    ต้องถามว่าเป็น:
    - VLAN หนึ่งรายการมี SVI/IPv4 Subnet ได้ 0 หรือ 1 รายการใน MVP ส่วน Trunk Port สามารถอนุญาต VLAN ได้หลายรายการ
    
    
3. **Credential มีความเสี่ยง**
	READ_ONLY — สำหรับ Discovery และ Monitoring
	CONFIG_WRITE — สำหรับ Deployment เท่านั้น
พร้อมกำหนดว่า Feature อื่นได้รับแค่ Credential Reference และห้ามอ่านรหัสผ่านโดยตรง
